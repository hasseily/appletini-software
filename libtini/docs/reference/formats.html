libtini

Data formats

The bytes the tools write and the library reads. Multi-byte numbers are little-endian unless a table says otherwise.

Packed pixels and the SHR screen

A pixel is a 4-bit palette index; a byte holds two, the left pixel in bits 7-4. A row of w pixels takes (w + 1) / 2 bytes.

AUX bank 0Contents
$2000-$9CFF200 rows of 160 bytes; row y starts at $2000 + 160y
$9D00-$9DC7One scan-line control byte per row; libtini writes 0: 320-pixel mode, palette 0
$9DC8-$9DFFPadding; libtini writes 0
$9E00-$9FFFSixteen palettes of sixteen 0RGB words; libtini uses palette 0 at $9E00

A palette word is 0x0RGB: four bits each of red, green and blue, so 0x0F00 is red and 0x0FFF white.

Palette JSON

["#000000", "#FFFFFF", "#FF0000", 255, 4095]

Up to sixteen entries, each a 0RGB integer 0-4095 or a "#RRGGBB" string, whose channels keep their high four bits. Missing entries are 0. assets.py image --palette-output writes the sixteen words as 32 bytes.

TPK1 resource packs

824 per entryThe directory

Entry offsetBytesContents
016Name, NUL-padded: a capital letter, then capitals, digits, . or _, at most 15 characters

Names are unique and in strictly increasing byte order; padding is all zero. Data starts after the directory and entries do not overlap, in name order. Every byte lies within the file, which fits ProDOS's 24-bit length. ti_pack_load checks all of this for every entry before it allocates memory. The pack manifest is {"entries": [{"name": "SHIP", "path": "ship.ti4"}]}, with entries of 1 byte to 4 MiB.

Pattern songs

What tools/music.py writes for a song document and ti_song_start reads.

OffsetBytesContents

then2 per noteTone periods for the 1 MHz base clock, 0-2047
then2 per patternOffset of each pattern from the song's first byte
thenpositions per trackPattern numbers, track 0's order first
thenPattern bytes
Pattern byteMeaning
$00-$5FPlay that note of the period table
$60Rest
$61Hold the current sound
$80 + nFollowing notes, rests and holds last n + 1 rows, 1-64
$C0 + v, $D0 + d, $E0 + fSet the track's volume, decay or floor
$FFEnd of the pattern

The row length, volume, decay and floor carry over into the next pattern. Every pattern starts after the tables, ends inside the song with $FF and holds at least one note, rest or hold.

At each row, a track whose note has ended reads its next note, rest or hold. A note sets the tone and starts at the track's volume; every decay ticks it falls one level, down to the floor, and decay 0 holds it. Decay runs before the row, so a note starts at full volume, and after a late update it catches up at most 16 ticks.

Song JSON

{"credit": "optional text for the header comment",
 "song": {"bpm": 152, "rows_per_beat": 8, "loop": 0,
   "tracks": [{"name": "lead", "volume": 12, "decay": 4, "floor": 8, "order": ["a", "a", "b"]}],
   "patterns": {"a": "D#5:2 F#5:2 -:4 G#5:8", "b": "v10 B5:12 ^:4"}}}
  • bpm 20-400 and rows_per_beat 1-16 must give rows of 1-100 ticks.
  • Tokens: NOTE:ROWS (rows 1-255), -:ROWS rest, ^:ROWS hold, vN, dN, fN with N 0-15. Notes are names with an optional # or b and an octave, C4 being MIDI note 60; each must have a period of 1-2047.
  • Tracks default to volume 12, decay 0, floor 0. Every order has the same number of positions, at most 255, and every track the same number of rows.
  • The compiler stores only the notes used, in pitch order, and only the patterns some order uses. A run of more than 64 rows becomes holds.

Event score JSON

{"voices": 6, "events": [{"duration": 0, "period": 956, "voice": 0, "volume": 7},
                         {"duration": 25, "period": 1517, "voice": 1, "volume": 5}]}

voices is 6 or 12. Each of 1-512 events has exactly the four keys: duration 0-65,535 ticks, period 0-2047, voice below voices, volume 0-15. The durations must not all be zero, and at most 31 zero durations may follow each other. The header holds a ti_music_event array, six bytes per event.

Speech JSON and phoneme bytes

{"phrases": {"SAY_READY": "Ready.", "SAY_SCORE": "Score 100!"},
 "pronunciations": {"UP": ["UH", "P"], "CLEAR": "K L IY R"}}
  • Phrase names are C identifiers in capitals: a capital or underscore, then capitals, digits or underscores.
  • Text holds letters, digits, spaces and . , ! ? ; : - ', which are ignored. A run of digits, 0-9999, becomes number words.
  • A pronunciation is a list or a space-separated string of phoneme names. Words are joined with a PA pause.

Each generated byte holds an SSI-263 phoneme code in bits 0-5 and a duration value in bits 6-7: 0 for vowels, 2 for stops and the pause, 1 for every other sound.
