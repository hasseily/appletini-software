libtini

Checks

libtini runs on Appletini hardware with firmware F1.3.2. The automated checks on this page test the tools and the compiled library on the host and on the emulator.

Two types of checks

TypeWhat runsWhat it tests
HostPython tests of the tools. The C game logic and input code, compiled with GCC.Formats, compilers, game rules and deterministic output
EmulatorThe linked 65C02 programs on py65, with independent memory and device models. The same programs on the native Appletini machine of the repository, at the vtw33 and turbo-f122 models.The bytes, register writes and results of the compiled code, and its time on the models

Run all checks

python -m pip install py65==1.2.0
python tools/check.py --cc65-home D:/Repos/cc65 --cc C:/msys64/ucrt64/bin/gcc.exe [--rom-boot] [--only NAME,NAME]

The runner builds the two variants. Then it runs each check in sequence, and it stops at the first failure. The logs go to build/checks/NAME.log, and the results go to build/checks/validation.json.

  • --only runs the named checks again and keeps the other recorded results.
  • --rom-boot adds ProDOS boots. They use the bundled boot ROMs in build-inputs/native-roms/. The text previews also need the separately installed apple2e-video.bin.
  • The Python that runs the checks must have py65 1.2.0. The native machine must be able to use the GCC folder.

The check scripts are in tests/. The runner is tools/check.py.
