libtini

Browser player

Run a libtini game in a web page: tools/web.py compiles the repository's development machine to WebAssembly and packages it with the game's own disk. The page runs the same 65C02 program as the board, so a game needs no changes.

STARFALL plays this way at appletini.org/demo/starfall. The player is an emulator: its timing is a model, and only a board establishes real timing and output.

Build and play locally

Install Emscripten 6.0.13 with emsdk (the tool refuses other versions), build the game's disk with tools/build.py, then:

python tools/web.py --emsdk D:/Repos/emsdk --game starfall --boot-roms build-inputs/native-roms --serve 8642

Open http://localhost:8642/, choose a speed and press Play. The output is build/web/GAME/, a folder of static files. Browsers allow audio worklets and module workers only over http://localhost or HTTPS, so open it through a server, not as a file; --serve serves it to this computer only, with the MIME types browsers need.

OptionEffect
--emsdk DIRThe installed emsdk; or set EMSDK
--game NAMEThe game under examples/, STARFALL by default
--boot-roms DIRBoot the whole disk through the installed enhanced //e ROM and slot-7 SmartPort firmware. The package then contains the Apple ROM and the disk's ProDOS.
--download-diskAlso offer the disk, with its ProDOS, as GAME.po beside the page
--serve PORTServe the page on http://localhost:PORT/ after building
--rebuildRebuild the WebAssembly player

Without --boot-roms, the player loads the disk's files, all but PRODOS, through the machine's ProDOS MLI stand-in, and the package contains only the game. That stand-in does not implement ALLOC_INTERRUPT, so ti_audio_init fails there and a game that needs the slot-4 clock reports it missing; STARFALL shows "SLOT 4 AUDIO REQUIRED". Use --boot-roms for such games.

What the page does

  • It runs whole NTSC frames, 262 lines of 63.695 µs, at the vtw33 model (33.33 MHz) or the turbo-f122 model (historical F1.2.2 TURBO costs), keeping 100 ms of audio queued, or by the wall clock without sound, at most four frames per display refresh.
  • A second instance of the module mixes SSI-263 speech in a Web Worker, as the native runner does. The page doubles speech before mixing, because the board's speech is louder than the reference model's.
  • After each frame it decodes SHR from AUX $2000-$9FFF and draws it at 640x400, the Appletini's square-pixel shape. Other video modes show black. It does not model the production capture stream.
  • Keys reach the //e as a held key with any-key-down. A gamepad drives paddles 0 and 1 and buttons 0-2.
  • Touch devices get a virtual stick, A and B buttons, Return and Esc keys and a Keyboard button that opens the device's keyboard; typed characters arrive in capitals. The controls appear on a coarse pointer or the first touch; ?touch=1 or ?touch=0 overrides that.
  • On iOS the page starts audio inside the Play tap and asks for the playback audio session, so sound plays with the silent switch on; the status line says "tap for sound" while sound is off.

Publishing a game page

Copy build/web/GAME/ to any static host that serves HTTPS. The page sets its base URL from its own location, so it works at any path. Every package carries COPYING.txt and source.zip, the player's Corresponding Source with its build record.

The player links the repository's GPL-3.0 emulator and speech code, so the player and its files in tools/web/ are GPL-3.0-only, unlike the MIT library. A published copy must offer its source, which the package does. A --boot-roms or --download-disk package also contains the Apple ROM and ProDOS; publish it only where you have the right to distribute them.

How it is checked

python tests/web_validate.py --emsdk D:/Repos/emsdk --cc C:/msys64/ucrt64/bin/gcc.exe --boot-roms build-inputs/native-roms

This runs a 1,100-frame STARFALL script in the player under Node and in the native machine with its separate speech worker: boot, launch with the Mockingboard, move, drop a bomb and use the joystick. At every checkpoint the tick count, program counter, AUX $2000-$9FFF and decoded frame must match, and so must the digest of the mixed audio. On 2026-10-22 both profiles matched at all nine checkpoints, with Node running at 2.08 times real time for vtw33 and 1.33 times for turbo-f122; a slower computer may not keep up with TURBO. No browser or board timing is claimed.
