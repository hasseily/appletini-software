libtini

Machine contract

What libtini expects of the machine at launch, what it changes and restores, and the rules for interrupts, memory mapping and shared devices. Read this before you add assembly, an interrupt handler or another driver to a libtini program.

Launch

A libtini program is a ProDOS SYS file, launched at $2000 on an enhanced //e (65C02). At entry:

  • Main memory is selected for reads and writes (RAMRD and RAMWRT off) and ALTZP is off.
  • The RamWorks selector is 0.
  • Appletini fake SHR is off: $C029 holds $01.
  • 80STORE, HIRES and PAGE2 do not redirect the instruction stream at $2000 to auxiliary memory.

A normal ProDOS launch from the text screen meets all of these. $C073 and $C029 cannot be read back, so their entry values are requirements, not something startup checks.

What startup changes

Before main, startup saves cc65's zero page ($80-$99), the 64 bytes at $0140 that the transfer trampoline will use, the entry processor status, 80STORE and six readable display switches. It masks interrupts, turns 80STORE off, copies the full-game layout's low segments into place, clears NEARBSS and BSS, sets up the C stack, installs the trampoline and enables interrupts again if they were enabled at entry. C runs in binary mode. The RESET vector, ProDOS's device list and the language card are left alone.

Exit

Returning from main or calling exit runs ti_shutdown, then restores main memory mapping, selector 0, fake SHR off, the saved display switches, 80STORE, the trampoline bytes, the zero page and the entry processor status, and calls ProDOS QUIT. It restores the OS state it saved, not the program's own low memory. Reset and power loss cannot run this.

If ti_shutdown fails because ProDOS refused to remove the audio interrupt handler, quitting would leave ProDOS calling into freed memory. Startup instead turns on the text screen, shows CLEANUP ERROR. KEY RETRIES; CODE RETAINED, and retries the shutdown on each key.

The bank grant

ti_init(first_bank, bank_count) is a grant from the game, not a discovery: grant a contiguous run of selectors 1-126 that no RAM disk or other program uses. The probe at AUX $A000 detects missing and aliased banks without keeping its writes; it does not certify every byte or identify the firmware. Selector 127 is outside the F1.3.2 baseline's first PSRAM chip and is rejected.

Mapping and transfers

  • Every public call runs in the foreground with main memory mapped, ALTZP and 80STORE off and selector 0. Calls are not reentrant.
  • A CPU transfer burst moves at most 128 bytes: it saves the processor status, masks interrupts, copies its parameters to main zero page, selects the bank, runs the copy loop from the trampoline at $0140, and restores main memory and selector 0 before the status. Callers with interrupts enabled get them back between bursts. The bound is a byte and instruction count, not a measured board time.
  • RAMRD also redirects instruction fetches, so only the page-one trampoline runs while auxiliary reads are mapped.
  • A bank 0 transfer, which every screen write is, relies on the selector already being 0 and writes no $C073, because any $C070-$C07F access also starts the paddle timers.
  • No pointer into a bank ever reaches C code.

Interrupts and NMI

  • An interrupt handler must not call libtini, change memory mappings or the selector, touch libtini's zero page or read granted banks. A C handler in switched memory is unsafe.
  • An NMI cannot be masked: an NMI handler must run safely while auxiliary reads are mapped, preserve every scratch location and follow the same rules.
  • libtini's own handler, the audio clock, is assembly registered through ProDOS. It counts ticks and acknowledges the timer without C, zero page, mapping changes or MLI calls. During a declared gap it declines every interrupt before touching slot I/O.
  • The hardware stack has 128 bytes, $0180-$01FF, for the program's deepest call chain plus ProDOS's interrupt dispatch. Measure both stacks when adding depth or interrupt nesting.

The screen

ti_gfx_begin saves all of AUX bank 0 from $2000 to $9FFF and turns on fake SHR by writing $C1 to $C029; ti_gfx_end writes $01 and restores every byte. Surfaces stay in banked memory and reach the screen only through CPU writes. A return from a publication means the writes finished: there is no page swap, no promise about the HDMI frame and no guaranteed deadline. Byte budgets are checked before writing; a measured deadline overrun is reported after.

ProDOS during a video session

ProDOS's /RAM can live in the same AUX bank 0 bytes as the picture, and a mode change alone does not make them safe. Each file call during a session therefore saves the picture to a temporary 32,768-byte resource, turns SHR off, restores the OS's bytes, calls ProDOS, saves the OS's changes into the session backup, then restores the picture and SHR. Audio init and shutdown do the same around ProDOS's interrupt calls. If the temporary resource cannot be allocated the call fails before ProDOS runs. No /RAM device is disconnected or reformatted. Handlers that use auxiliary memory while SHR is shown remain excluded.
