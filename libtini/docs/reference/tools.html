setup_inputs.py

python tools/setup_inputs.py

Downloads the official ProDOS 8 2.4.3 140 KiB image named in tools/prodos-input.json, checks its SHA-256 and writes it to build-inputs/prodos/ProDOS_2_4_3.po. If the file is already there it only checks the hash. This is the only tool that uses the network. The repository does not redistribute ProDOS.

assets.py

python tools/assets.py image   INPUT.ppm  OUTPUT.ti4 --palette PALETTE.json [--palette-output FILE] [--masked] [--report FILE]
python tools/assets.py indexed INPUT.json OUTPUT.ti4 [--report FILE]
python tools/assets.py font    INPUT.json OUTPUT.tif [--report FILE]
python tools/assets.py map     INPUT.json OUTPUT.tim [--report FILE]
python tools/assets.py pack    PACK.json  OUTPUT.tpk [--report FILE]
CommandInputOutput
imageP3 or P6 PPM, 8-bit channels, 1-320 by 1-200, matched to the palette by nearest colourTI4; --masked appends an opacity mask; --palette-output writes the 32-byte palette
indexedJSON width, height, pixels (0-15), optional maskedTI4

Every command prints, and with --report writes, the output size and the least number of 48,640-byte banks it needs. Outputs contain no timestamps. Formats are in Data formats; usage is in Art, fonts, maps and packs.

speech.py

python tools/speech.py PHRASES.json --preview
python tools/speech.py PHRASES.json --output HEADER.h [--symbol NAME] [--no-numbers]

Compiles each phrase's text to SSI-263 phoneme bytes with a small authored English vocabulary and the file's pronunciations. Unknown words, unsupported characters and phrases over 255 phonemes fail. The header defines each phrase name as its number and a ti_speech_bank named NAME (default ti_speech_assets), with the thirty number words unless --no-numbers. A bank holds up to 225 phrases with number words or 255 without. --preview prints each phrase's phonemes and an estimated length at rate 10; it makes no sound.

music.py

python tools/music.py SOURCE.json --preview
python tools/music.py SOURCE.json --output HEADER.h [--symbol NAME] [--report FILE]

A document with events becomes a ti_music_event array named NAME (default score) and NAME_COUNT, in capitals. A document with song becomes the pattern-song bytes in a uint8_t array and NAME_SIZE. The report gives the event or row count, the size and the nominal length at 100 ticks a second. An optional credit string is repeated in the header's comment.

midi.py

python tools/midi.py TUNE.mid ARRANGEMENT.json --output SONG.json

Arranges a Standard MIDI File as a song document for music.py, using the arrangement's bars, loop bar, rows per beat and tracks. It prints, per channel, the notes no track took. The MIDI file is only read; builds use the song document. See Arranging a MIDI file.

starfall_assets.py

python tools/starfall_assets.py --header build/starfall_assets.h [--preview build/starfall-art.ppm]

Checks the SHA-256 of the vendored Kenney archive in assets/starfall/, reads its indexed PNGs with a small built-in PNG reader, and writes STARFALL's sixteen 16x16 cells, palette and sub-sprite table as a C header. --preview writes an enlarged contact sheet. It is an example of a game-specific generator; assets/starfall/README.md describes the conversion.

disk.py

A library module, not a command. It writes deterministic ProDOS-order volumes with a root directory of seedling and sapling files, copying the boot blocks and unmodified PRODOS kernel from the installed release, and validates directory links, block ownership, the allocation bitmap and every payload. build.py and a separate project's build.py use it.

native_emulator.py

python tools/native_emulator.py --cc GCC [--rebuild] build
python tools/native_emulator.py --cc GCC run  --disk DISK.po --system NAME.SYSTEM --profile vtw33 --frames 120 --screenshot OUT.png
python tools/native_emulator.py --cc GCC play --disk DISK.po --boot --rom ROM --slot7-rom C700 --slot7-c8-rom C800 [--video-rom CHARROM]

Builds the repository's development machine, ../tools/appletini and ../demos/doom_gs/tools/a2vm, as build/native/libappletini.dll with GCC, without changing its sources, and passes the remaining arguments to the runner. --disk with --system launches one SYS file through a ProDOS MLI stand-in; --boot boots the disk through ROMs that must be installed under build-inputs/. --profile is vtw33 or turbo-f122. This wrapper runs without sound synthesis. The emulator is GPL-3.0-only and is not linked into any libtini program.

profiler.py

python tools/profiler.py --game starfall --cc65-home D:/Repos/cc65 --cc C:/msys64/ucrt64/bin/gcc.exe `
    --key 13 --skip 360 --frames 1200 --count _sf_frames:4 _render _hud _field _ti_gfx_text_opaque

Boots a game that build.py built, from the installed ROMs, waits for main, sends the keys in order and measures a window of emulator frames. Each named function's time includes everything it calls, interrupts too, and is reported per call path such as _hud/_field/_ti_gfx_text_opaque, with calls, milliseconds a call and share of the window. Exported names come from the label file; static C functions and other labels come from listings of the staged sources, and a name several modules share is given as module:name. --count LABEL:BYTES reports how much a variable changed.

OptionDefaultMeaning

--wait600Frames after main starts
--keyA key code or character; repeatable
--key-frames30Frames after each key
--skip0Frames before the window
--frames600Frames in the window
--outputbuild/profile/The JSON report

benchmark.py

python tools/benchmark.py --cc65-home D:/Repos/cc65 --cc C:/msys64/ucrt64/bin/gcc.exe [--private] [--boot-roms build-inputs/native-roms] [--repeat 2]

Builds examples/benchmark.c as its own program and disk, runs it on the emulator and records CPU cycles, profile clock ticks, instruction and I/O counts and modelled time for cross-bank resource writes, reads, fills and copies, a full publication and a dirty rectangle, checking every result. --private also builds and measures the AMEM variant; --boot-roms boots through installed ROMs, which lets the emulated controller provide AMEM. Repeated runs must give identical counters. Results go to build/benchmark/results.json. Recorded results are in design/BENCHMARKS.md.

reference_guard.py

python tools/reference_guard.py ROOT RECORD.json
python tools/reference_guard.py ROOT RECORD.json --check

Records a fingerprint of a reference checkout's files before it is read and checks afterwards that nothing changed. It is an audit aid, never a build input.

Installed tool versions, hashes and licences are in tools/DEPENDENCIES.md.
