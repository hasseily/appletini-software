libtini

Optional AMEM

#include "libtini/amem.h"

Acceleration of large banked transfers through Appletini's private AMEM memory service, behind the ordinary resource API. The default build leaves the transport out; the CPU path is always present and is the reference.

FunctionPurpose
ti_amem_enableIdentify the controller and service, then use it for eligible transfers
ti_amem_disableGo back to CPU transfers
ti_amem_availableWhether acceleration is active
ti_amem_last_errorThe controller's last error byte

Building with AMEM

python tools/build.py --cc65-home D:/Repos/cc65 --private --build-dir build/private

This builds the library and every game whose manifest does not set "private": false again, with TI_PRIVATE_TRANSPORT=1 and the slot-7 FIFO transport, into build/private/. The CPU-only outputs in build/ are not touched. STARFALL has no AMEM build. In the default build the four functions exist but enable returns TI_E_UNAVAILABLE.

What it accelerates

  • ti_res_read, ti_res_write and ti_res_fill of 256 bytes or more.
  • ti_res_copy of 256 bytes or more between two different resources. Copies within one resource, overlapping or not, stay on the CPU.
  • Large operations split at each bank boundary, with the same checks and buffer lifetimes as the CPU path. Each request targets private working memory only.

The screen is never written through AMEM: publication, the video session's backup and restore, and storage's screen loans always use CPU writes. AMEM is not a framebuffer blitter. Its request overhead can cost more than a CPU loop for small transfers; see the benchmark notes.

Failure rules

A service that is missing, unsupported or unavailable before a transfer's first request makes that transfer use the CPU instead, silently. Once part of a transfer has gone through AMEM, any failure returns TI_E_IO: earlier pieces may already have changed the destination, so the library never repeats the operation with CPU copies. Treat the destination as possibly partial and recover at your own transaction boundary.

A failed request, a response that never arrives or a malformed response also poisons the driver for the rest of the program: later enables and transfers return TI_E_IO without sending anything. The wait for a response is bounded by 240 changes of the //e vertical blank flag, 2 seconds at 60 Hz and 2.4 at 50 Hz, whatever the CPU speed; the time the controller holds the CPU does not count. Do not use disable and enable again as an automatic retry after an uncertain failure.

Functions

ti_amem_enable

ti_error ti_amem_enable(void);

Call after ti_init. With interrupts masked, it takes the slot-7 expansion ROM space, saves INTCXROM, and checks the C700 ROM: its signature bytes and a CRC-16/CCITT-FALSE of $95D9 over the 256 bytes, which identifies the controller; F1.3.1 and F1.3.2 share that ROM. An unidentified controller receives nothing. A matching one gets a STATUS request for the AMEM service, which must report the AMEM signature, a supported major version and descriptor size, copy and fill support, the $0200-$BFFF windows and PRIVATE support. The transport then restores the caller's interrupt state and INTCXROM and deselects the expansion ROM; a previously selected expansion ROM is not reselected.

Every later transfer repeats the STATUS check before its first request and checks the reported highest bank. The audio driver is paused around each request, and long requests mark a timing gap.

Returns

TI_OK when acceleration is active; TI_E_UNAVAILABLE for an unidentified controller, a service that reports itself unavailable or unsupported, or a CPU-only build; TI_E_IO for a poisoned driver or a failed STATUS exchange.

ti_amem_disable

void ti_amem_disable(void);

Removes the acceleration hooks; transfers use the CPU. It does not clear poisoning or repair partly changed data. ti_shutdown also removes the hooks, and a new ti_init needs a new enable.

ti_amem_available

uint8_t ti_amem_available(void);

1 while acceleration is enabled, not poisoned and hooked in; 0 in a CPU-only build.

ti_amem_last_error

uint8_t ti_amem_last_error(void);

The last error byte from the controller, or the driver's own: $61 for a malformed STATUS reply and $67 for a response timeout. A CPU-only build returns $21.

The transport has been checked against a modelled controller and FIFO, not on the selected firmware. No other foreground code or NMI handler may claim the slot-7 expansion ROM or the FIFO at $CFF0-$CFF2 while a request runs.

Defined in include/libtini/amem.h, implemented in src/amem.c, src/memory.c, src/memory_copy.c and src/optional/amem_transport.s.
