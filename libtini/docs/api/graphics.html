libtini

Graphics

#include "libtini/graphics.h"

Software surfaces in banked memory, drawing into them, and publishing them to the 320x200 Super Hi-Res screen with ordinary CPU writes. For many moving sprites over a plain background, see sprite scenes.

Pixels, surfaces and the screen

A pixel is a 4-bit palette index. Two pixels share a byte, the left one in the high nibble. A surface row of width w takes (w + 1) / 2 bytes, its stride; an odd width leaves the last low nibble unused.

The Super Hi-Res screen uses the same packing: 200 rows of 160 bytes at AUX $2000, then 200 scan-line control bytes at $9D00 and sixteen palettes at $9E00. libtini sets every line to 320-pixel mode with palette 0, so the whole screen shares one palette of sixteen 0RGB colours.

Surfaces live in banked memory. Drawing changes a surface only; nothing appears until ti_gfx_present copies a rectangle of a 320x200 surface to the screen. Keep the surface authoritative: publication reads the bytes it writes from it, including the neighbour pixel of a partly covered byte.

Types

ti_surface

typedef struct ti_surface {
    ti_handle pixels;
    uint32_t offset;   /* permits a borrowed view into one resource pack */
    uint16_t width, height, stride;
} ti_surface;

Packed pixels in a resource, starting offset bytes in. Width is 1-320, height 1-200 and stride must equal (width + 1) / 2; every drawing call checks this and the resource's extent before it starts.

A surface made by ti_gfx_surface_create owns its resource. A copy of the structure, or a surface filled in by hand to view an image inside a pack, only borrows the resource: never free a borrowed view, and stop using every view before the owner is freed.

ti_rect

typedef struct ti_rect { int16_t x, y; uint16_t width, height; } ti_rect;

A rectangle with a signed position. Calls clip it to the surface unless their entry says otherwise.

ti_gfx_stats

typedef struct ti_gfx_stats { uint32_t bytes, elapsed_ticks; uint8_t flags; } ti_gfx_stats;

Filled by a publication: the bytes written to the screen, the ticks it took when a budget clock is set, and the TI_GFX_* flags.

ti_sprite

typedef struct ti_sprite { ti_surface image; ti_handle mask; uint32_t mask_offset; } ti_sprite;

An image with an optional opacity mask: one bit per pixel, high bit first, 1 for opaque, each row (image.width + 7) / 8 bytes. With mask 0, colour 0 is transparent instead. Image and mask may share one resource at different offsets; both are borrowed.

ti_tileset

typedef struct ti_tileset {
    ti_surface image;
    uint8_t tile_width, tile_height, columns;
    uint16_t count;
} ti_tileset;

An atlas of count tiles (1-256), columns to a row, numbered left to right, top to bottom. The atlas must hold columns * tile_width pixels across and enough rows of tiles for count.

ti_tilemap

typedef struct ti_tilemap {
    ti_handle cells;   /* row-major uint8 tile IDs */
    uint32_t offset;
    uint16_t columns, rows;
} ti_tilemap;

A map of 1-256 by 1-256 one-byte tile numbers in a resource.

ti_animation

typedef struct ti_animation { uint16_t first, count, ticks_per_frame; } ti_animation;

A run of count frame numbers starting at first, each shown for ticks_per_frame device ticks.

ti_bitmap_font

typedef struct ti_bitmap_font {
    ti_handle glyphs;
    uint32_t offset;
    uint8_t width, height, first, count; /* one byte per glyph row, MSB first */
} ti_bitmap_font;

Glyphs of 1-8 by 1-16 pixels for character codes first to first + count - 1, stored in a resource as height bytes per glyph, the leftmost pixel in the high bit. tools/assets.py font produces this layout after an 8-byte header.

Surfaces

ti_gfx_surface_create

ti_error ti_gfx_surface_create(ti_surface *surface, uint16_t width, uint16_t height);

Allocates a resource of stride * height bytes and fills in *surface. The pixels are not cleared: call ti_gfx_clear before publishing. The structure must be zero-initialized first, as static and global structures are.

Returns

TI_OKThe surface owns a new resource.
TI_E_ARGUMENTsurface is not writable near memory.
TI_E_STATEsurface->pixels is not zero: the structure already owns a resource, or was not initialized.
TI_E_RANGEWidth outside 1-320 or height outside 1-200.
TI_E_NOMEM, TI_E_STATEFrom ti_res_alloc: no slot or room, or no ti_init. The structure's sizes are zeroed.

ti_gfx_surface_free

ti_error ti_gfx_surface_free(ti_surface *surface);

Frees the surface's resource and zeroes the structure, so it can be created again.

Returns

TI_OK; TI_E_ARGUMENT for an unwritable pointer; TI_E_HANDLE when the resource is not live, as after a second free.

Drawing

Drawing calls are synchronous, foreground-only and non-reentrant. Strings and structures need to stay valid only until the call returns. Every call first checks the surface: TI_E_ARGUMENT for an unreadable structure or inconsistent sizes, TI_E_HANDLE for a dead resource, TI_E_RANGE when the pixels pass the resource's end. Colours are 0-15; a larger colour returns TI_E_ARGUMENT.

Rectangles, text, clearing and publication move whole rows between the surface's bank and a near row buffer with one assembly routine. Lines and bitmap fonts plot single pixels through a 128-byte cache, and blits, sprites and maps go through resource reads and writes, so they cost more per pixel. A program that only fills rectangles and uses the built-in font does not link the pixel cache.

A resource error in the middle of a draw can leave part of it done. Drawing is not transactional; stop or redraw from a known state.

ti_gfx_clear

ti_error ti_gfx_clear(ti_surface *surface, uint8_t color);

Fills the whole surface with color, the unused padding nibble of odd-width rows included.

ti_gfx_rect

ti_error ti_gfx_rect(ti_surface *surface, int16_t x, int16_t y,
                     uint16_t width, uint16_t height, uint8_t color);

Fills a rectangle, clipped to the surface. A rectangle that is entirely outside returns TI_OK without drawing. It builds one row of bytes and writes it to every line; when an edge falls inside a byte it reads each line first so the outside pixel keeps its colour.

ti_gfx_line

ti_error ti_gfx_line(ti_surface *surface, int16_t x0, int16_t y0,
                     int16_t x1, int16_t y1, uint8_t color);

Draws a Bresenham line, both endpoints included, clipped pixel by pixel. Endpoints must lie in -1024 to 1024 on both axes, which bounds the work; others return TI_E_RANGE.

ti_gfx_text

ti_error ti_gfx_text(ti_surface *surface, int16_t x, int16_t y,
                     const char *text, uint8_t color);

Draws a NUL-terminated string in the built-in font. Each character is a 5x7 glyph in a 6x8 cell whose top-left corner is at the pen position; the pen then moves 6 pixels right. A newline (byte 10) returns to x and moves down 8 pixels. Only lit pixels are drawn: the rest of the cell keeps its colours. Text is clipped to the surface.

The font has the space, ! " ' ( ) * + , - . /, the digits, : < = > ?, the capital letters and [ ] _. Lower-case letters are drawn as capitals. Every other byte is drawn as ?.

A call reads at most 1024 characters, newlines included. Each pixel row of a line of text is one read and one write of the bytes it covers.

Returns

TI_OK; TI_E_ARGUMENT for a NULL string or a colour above 15; TI_E_RANGE when x or y is outside -1024 to 1024, or when the string runs out of readable near memory before its NUL (lines before that point are drawn).

ti_gfx_text_opaque

ti_error ti_gfx_text_opaque(ti_surface *surface, int16_t x, int16_t y,
                            const char *text, uint8_t color, uint8_t background);

Draws like ti_gfx_text, but fills every whole 6x8 cell, its gap column and eighth row included, with background first. A new value then covers an older one of the same length without clearing a rectangle, and the area to publish is exactly 6 * length by 8 pixels. It writes rows without reading them unless a line's edge splits a byte.

static const ti_rect score_cells = {250, 64, 7 * 6, 8};
char text[8];
ti_gfx_text_opaque(&canvas, 250, 64, ti_digits(text, score, 7), 9, 0);
ti_gfx_present(&canvas, &score_cells, 0);   /* publish just those cells */

ti_digits

char *ti_digits(char *text, uint32_t value, uint8_t count);

Writes exactly count decimal digits of value, zero padded, and a NUL. A value with more digits keeps its last count: ti_digits(s, 123456, 4) writes "3456". count is 1-10 and text needs count + 1 writable near bytes.

Returns text, or NULL for a bad count or buffer. The text functions reject NULL with TI_E_ARGUMENT, so the result can be passed straight to them. It is written in assembly and doubles a BCD number instead of dividing by ten.

ti_gfx_text_font

ti_error ti_gfx_text_font(ti_surface *surface, int16_t x, int16_t y,
                          const char *text, uint8_t color, const ti_bitmap_font *font);

Draws a string in a bitmap font. Each glyph's lit pixels are drawn; the pen then moves width + 1 pixels. A character outside the font leaves a blank advance. A newline returns to x and moves down height + 1 pixels. At most 1024 characters are read.

Returns

TI_OK; TI_E_ARGUMENT for a NULL or unreadable font or string, a colour above 15, or font sizes outside 1-8 by 1-16 with first + count above 256; TI_E_RANGE when the glyphs pass the resource's end or the string runs out of near memory; TI_E_HANDLE for a dead glyph resource.

ti_gfx_blit

ti_error ti_gfx_blit(ti_surface *destination, int16_t x, int16_t y,
                     const ti_surface *source, const ti_rect *source_rectangle,
                     uint8_t transparent_color);

Copies a rectangle of source to destination with its top-left corner at x, y, clipped to the destination. NULL selects the whole source. Pixels of transparent_color (0-15) are skipped; TI_GFX_OPAQUE copies every pixel. Odd source and destination positions both work. The copy runs in pieces of up to 240 pixels per row through near buffers.

Returns

TI_OK; TI_E_ARGUMENT when both surfaces use the same resource handle (copies within one resource are rejected before any change), for a colour key that is neither 0-15 nor 255, or an unreadable rectangle; TI_E_RANGE when the source rectangle is not wholly inside the source; the surface errors above.

ti_gfx_sprite

ti_error ti_gfx_sprite(ti_surface *destination, int16_t x, int16_t y,
                       const ti_sprite *sprite);

Draws a whole sprite image, clipped. With a mask, a mask bit of 1 copies its pixel, colour 0 included, and 0 leaves the destination pixel. Without one, colour 0 is transparent. The mask must not use the destination's handle, and the image the same rules as a blit source.

Returns

As ti_gfx_blit; also TI_E_ARGUMENT for an unreadable sprite and TI_E_RANGE or TI_E_HANDLE when the mask does not fit its resource.

ti_gfx_map

ti_error ti_gfx_map(ti_surface *destination, const ti_rect *viewport,
                    const ti_tileset *tiles, const ti_tilemap *map,
                    uint16_t camera_x, uint16_t camera_y);

Fills viewport, clipped to the destination, with the part of the map whose top-left world pixel is camera_x, camera_y. Tiles are copied opaquely. Pixels beyond the map's edge are colour 0. Scroll by changing the camera.

Returns

TI_OK; TI_E_ARGUMENT for an unreadable viewport, tile set or map; TI_E_RANGE for zero or oversized tile or map sizes, an atlas too small for its tiles, a camera position plus viewport past 65,535, or a map cell whose tile number is not below count (found while drawing, so earlier tiles are drawn); surface and handle errors from the atlas, cells or destination.

ti_gfx_animation_frame

uint16_t ti_gfx_animation_frame(const ti_animation *animation, uint32_t elapsed_ticks);

Returns first + (elapsed_ticks / ticks_per_frame) % count. Pass elapsed device ticks, not a count of drawn frames, so the animation keeps its speed when drawing slows. Returns 0 for a NULL or unreadable descriptor, a zero count or ticks_per_frame, or first + count past 65,535.

The video session

ti_gfx_begin

ti_error ti_gfx_begin(const uint16_t *palette);

Takes the screen. It allocates a 32,768-byte resource and saves all of AUX bank 0 from $2000 to $9FFF into it, turns the Appletini's SHR display on, sets all 200 scan lines (and the padding after them) to 320-pixel mode with palette 0, and writes palette, sixteen 0RGB words from 0x000 to 0xFFF. It changes no slot or speed setting. The pixel area still holds whatever was there, so publish a cleared surface straight away.

Returns

TI_OKThe session is active.
TI_E_STATEA session is already active, or there is no ti_init grant for the backup.
TI_E_ARGUMENTpalette is not 32 readable near bytes.
TI_E_RANGEAn entry is above 0x0FFF.
TI_E_NOMEMNo slot or room for the backup; the screen is unchanged.

ti_gfx_palette

ti_error ti_gfx_palette(const uint16_t *palette);

Replaces the sixteen colours during a session with one 32-byte write. It is cheap enough to call every frame: changing a few entries animates every pixel that uses them without drawing.

Returns

TI_OK; TI_E_STATE without a session; TI_E_ARGUMENT or TI_E_RANGE as for ti_gfx_begin.

ti_gfx_end

ti_error ti_gfx_end(void);

Turns SHR off, writes every saved byte back to AUX bank 0 and frees the backup. Without a session it does nothing and returns TI_OK. ti_shutdown calls it.

If a file call has lent the screen memory to ProDOS during the session, the backup holds the OS's newer bytes, so ProDOS's /RAM changes survive.

ti_gfx_budget

void ti_gfx_budget(uint16_t byte_budget, ti_tick_source clock, uint32_t tick_budget);

Sets the limits that ti_gfx_present and ti_gfx_present_rows apply. A publication of more than byte_budget bytes is rejected before any write; 0 means 32,000, a full screen. With a clock, each publication is timed; a nonzero tick_budget that the time exceeds sets TI_GFX_OVERRUN. NULL clock leaves elapsed time unmeasured. Tick differences are modulo 232.

/* At most 4000 bytes a publication, and report one that takes over 2 ticks. */
ti_gfx_budget(4000, ti_audio_ticks, 2);

ti_gfx_present

ti_error ti_gfx_present(const ti_surface *surface, const ti_rect *rectangle,
                       ti_gfx_stats *stats);

Copies a rectangle of a 320x200 surface to the same place on the screen. NULL publishes the whole screen. The rectangle is clipped, and its left and right edges are widened to whole bytes. Each row goes through the near row buffer in bursts of at most 128 bytes. stats may be NULL.

A return means the CPU writes have finished. It does not mean the Appletini has shown them: there is no page swap, so a large rectangle can appear across two frames.

Returns

TI_OKPublished. A rectangle entirely off the surface publishes nothing and reports 0 bytes.
TI_E_STATENo video session.
TI_E_RANGEThe surface is not 320x200.
TI_E_ARGUMENTAn unreadable rectangle or unwritable stats.
TI_E_TIMINGBefore writing: the byte count exceeds the budget, and nothing was written. After writing: the measured time exceeded the tick budget; stats has TI_GFX_OVERRUN.

ti_gfx_present_rows

ti_error ti_gfx_present_rows(uint16_t x, uint16_t y, uint16_t width,
                            uint16_t height, const uint8_t *pixels,
                            uint16_t stride, ti_gfx_stats *stats);

Publishes packed pixels from near memory during a session, without a surface: row r of the rectangle comes from pixels + r * stride, and only width / 2 bytes of each row are written. Use it for small areas the game composes itself. It does not clip or widen edges, and it does not update any surface.

x, width
Even, so every row starts and ends on a byte.
y, height
The rectangle must be nonempty and lie wholly within 320x200.
pixels
The first byte supplies the two leftmost pixels. The span (height - 1) * stride + width / 2 must be readable near memory; the buffer is borrowed until return.
stride
Bytes from one source row to the next, at least width / 2. Padding and odd strides are fine.

All checks, the byte budget included, finish before the first write; a rejected call leaves stats unchanged. One assembly routine writes every row, each in one interrupt-masked burst, or two when it exceeds 128 bytes.

Returns

TI_OK; TI_E_STATE without a session; TI_E_ARGUMENT for zero width or height, NULL pixels or unwritable stats; TI_E_RANGE for odd x or width, a rectangle off the screen, a short stride or an unreadable span; TI_E_TIMING as for ti_gfx_present.

What drawing costs

These figures were measured on the development emulator's models, not on a board: vtw33 runs at a nominal 33.33 MHz, and the TURBO figure uses historical F1.2.2 costs. Use them to compare approaches; measure on the board before setting a game's budgets.

OperationBytesvtw33 msTURBO model ms
Publish the full screen32,00040.885.1
Draw a 65x17 rectangle at odd x5611.62.6
Publish that rectangle5611.32.1
Replace a 2-8 character HUD value with opaque text and publish its cells1.91.5

A full-screen publication takes more than one 60 Hz frame. Draw static parts once and publish only the rectangles that change.
