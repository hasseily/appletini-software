Memory

#include "libtini/memory.h"

The bank grant, checked near moves and fills, and banked resources: allocation, release, reads, writes, fills and copies.

Rules that apply to every call

  • Calls are foreground-only and non-reentrant. No interrupt handler may call them.
  • All handles, ranges and near buffers are checked before anything is changed. Bounds use subtraction, so offsets near 232 cannot wrap past a check.
  • An offset equal to a resource's size is valid only with a zero length. A zero-length call still needs a live handle and touches nothing.
  • Near buffers are borrowed only until the call returns. No call keeps a pointer, and no call returns a pointer into a bank.
  • CPU transfers split at the end of each bank and into bursts of at most 128 bytes. Each burst saves the processor status, masks interrupts, maps the bank, copies from the page-one trampoline and restores main memory and selector 0 before restoring the status. A caller with interrupts enabled gets them back between bursts.
  • Successful transfers mark a display-timing gap (ti_time_note_gap): a long transfer can hide vertical blank edges.

Functions

ti_init

ti_error ti_init(uint8_t first_bank, uint8_t bank_count);

Grants the RamWorks selectors first_bank to first_bank + bank_count - 1 to the library for resources. The grant is a promise from the game that nothing else uses those banks, such as a RAM disk driver; libtini cannot discover ownership.

Before it accepts the grant it saves one byte at AUX $A000 of bank 0 and of every granted bank, writes a different test value to each, reads them all back and restores the originals. This finds missing banks and banks that alias each other or bank 0. It does not test every byte or identify the firmware.

first_bank
The first selector, 1 to 126. Selector 0 holds the OS and the screen and is never granted.
bank_count
At least 1; the last selector must be at most 126. The F1.3.2 baseline serves selectors 0 to 126 from its first 8 MiB PSRAM chip, so 127 is rejected.

Returns

TI_OKThe grant is active; capacity is bank_count * TI_BANK_BYTES.
TI_E_STATEThe library is already initialized.
TI_E_ARGUMENTZero banks, bank 0, or a range past 126.
TI_E_UNAVAILABLEThe probe found a missing or aliased bank. The probe bytes are restored.
/* A 320x200 canvas, the screen backup and audio's temporary loan
 * need 97,536 bytes: three banks. */
if (ti_init(1, 3) != TI_OK) return 1;

ti_shutdown

ti_error ti_shutdown(void);

Shuts down audio if it is running (which also ends the video session first, so ProDOS gets its AUX bytes back before the interrupt handler is removed), ends the video session and restores the saved screen bytes, removes optional AMEM hooks, releases every resource slot and ends the grant. Calling it again does nothing and returns TI_OK. The program's startup code calls it when main returns.

Releasing a slot advances its generation, so every handle from before the shutdown becomes invalid, even after a new ti_init in the same run.

Returns

TI_OKEverything was released.
TI_E_IOProDOS refused to remove the audio interrupt handler. Audio is silent, but its handler code and the remaining resources are kept; call ti_shutdown again to retry.

ti_near_move

ti_error ti_near_move(void *dst, const void *src, uint16_t length);

Copies length bytes with memmove semantics: overlapping ranges copy correctly in both directions. The destination must lie wholly in one writable near region and the source in one readable region. A zero length accepts NULL pointers.

Returns

TI_OK, or TI_E_RANGE when either range leaves its region; nothing is copied then.

ti_near_fill

ti_error ti_near_fill(void *dst, uint8_t value, uint16_t length);

Writes value to length bytes of writable near memory.

Returns

TI_OK, or TI_E_RANGE when the range leaves its region.

ti_res_alloc

ti_error ti_res_alloc(uint32_t size, ti_handle *out);

Allocates size contiguous bytes in the granted banks, first fit. The bytes are not cleared. The allocation can cross bank boundaries; the library splits transfers there.

size
1 up to the free capacity.
out
A writable near ti_handle. It receives the handle, or TI_INVALID_HANDLE on any failure after the pointer check.

Returns

TI_OKThe handle is in *out.
TI_E_ARGUMENTout is not writable near memory, or size is zero.
TI_E_STATENo ti_init grant is active.
TI_E_NOMEMAll eight slots are in use, or no free run of size bytes remains.

A slot whose generation reaches 4095 retires instead of wrapping to a value an old handle might still hold. A program would have to allocate and free one slot thousands of times for that to matter.

ti_res_free

ti_error ti_res_free(ti_handle handle);

Releases the resource. Every copy of the handle, and every surface, sprite, font or map view that borrows it, becomes invalid.

Returns

TI_OK, or TI_E_HANDLE for a handle that is not live, including a second free.

ti_res_read

ti_error ti_res_read(ti_handle handle, uint32_t offset, void *dst, uint16_t length);

Copies length bytes starting at offset in the resource into the near buffer dst.

Returns

TI_OKThe bytes were copied.
TI_E_HANDLEThe handle is not live.
TI_E_RANGEThe range passes the resource's end, or dst is not writable near memory for length bytes.
TI_E_IOOptional AMEM build only: a submitted accelerated transfer failed. See AMEM.

ti_res_write

ti_error ti_res_write(ti_handle handle, uint32_t offset, const void *src, uint16_t length);

Copies length bytes from the near buffer src into the resource at offset. The source may be any readable near memory, constants included.

Returns

As ti_res_read; TI_E_RANGE also when src is not readable near memory.

ti_res_fill

ti_error ti_res_fill(ti_handle handle, uint32_t offset, uint8_t value, uint32_t length);

Writes value to length bytes of the resource. The length is 32 bits, so one call can fill a whole multi-bank resource.

Returns

TI_OK, TI_E_HANDLE, TI_E_RANGE, or in the optional AMEM build TI_E_IO.

ti_res_copy

ti_error ti_res_copy(ti_handle dst, uint32_t dst_offset,
                     ti_handle src, uint32_t src_offset, uint32_t length);

Copies length bytes from one resource to another, or within one resource, with memmove semantics in both overlap directions. The CPU path moves the bytes through a 128-byte staging buffer in main memory. Distinct live allocations never overlap, so only a same-handle copy can overlap.

Returns

TI_OK; TI_E_HANDLE if either handle is not live; TI_E_RANGE if either range passes its resource's end; in the optional AMEM build TI_E_IO.

/* Scroll a 64-row map buffer up by one 32-byte row, in place. */
ti_res_copy(map, 0, map, 32, 63UL * 32);

Example: a level buffer in a bank

#include "libtini.h"

#define LEVEL_BYTES 20000UL
static ti_handle level;
static uint8_t row[64];                 /* near working buffer */

ti_error load_level(void)
{
    ti_error e = ti_res_alloc(LEVEL_BYTES, &level);
    if (e) return e;
    e = ti_res_fill(level, 0, 0, LEVEL_BYTES);      /* allocations start uninitialized */
    if (e) return e;
    /* ... write rows from a pack or generator ... */
    return TI_OK;
}

uint8_t tile_at(uint16_t x, uint16_t y)
{
    /* Read a whole row once, then index it near. */
    ti_res_read(level, (uint32_t)y * 64, row, sizeof(row));
    return row[x];
}
