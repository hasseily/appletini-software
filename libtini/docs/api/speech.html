Speech

#include "libtini/audio.h"

Prepared phrases and spoken numbers through the SSI-263 on the slot-4 card. Text becomes phonemes on the host, with tools/speech.py; the game names phrases by generated identifiers and the audio driver plays them one phoneme per update.

Setting up speech

Speech is part of the audio driver: set speech in the audio configuration, start audio, then bind the bank that tools/speech.py generated. Keep calling ti_audio_update: it sends the next phoneme when the chip reports the last one finished.

python tools/speech.py speech.json --preview
python tools/speech.py speech.json --output build/my_speech.h --symbol my_speech
#include "my_speech.h"     /* SAY_READY, SAY_GAME_OVER, ... and my_speech */

static ti_audio_config audio = {TI_AUDIO_MOCKINGBOARD, 1, 1, 0, 0};

ti_audio_init(&audio);
ti_speech_bind(&my_speech);
ti_speech_say(SAY_READY, 1);
ti_speech_number(score, 1);         /* "one thousand nine hundred eighty four" */

The phrase file and the compiler's vocabulary are described in Music, effects and speech and Data formats.

Queue and priorities

One phrase speaks while up to four more wait (TI_SPEECH_QUEUE). A priority is 0-127; the waiting phrase with the highest priority speaks next, and equal priorities keep their order. Adding TI_SPEECH_INTERRUPT (128) to the priority starts the phrase at once, cutting off the current one if the new priority is at least as high; the waiting queue is kept. A number is one queue item even when it joins several words.

ti_phrase

typedef struct ti_phrase { const uint8_t *data; uint8_t length; } ti_phrase;

One prepared phrase: 1-255 SSI-263 phoneme bytes in near memory. Repeated phonemes stay separate writes to the chip.

ti_speech_bank

typedef struct ti_speech_bank {
    const ti_phrase *phrases;
    uint8_t count;
    const uint8_t *number_ids; /* 0..19, twenty..ninety, hundred, thousand; NULL omits numbers */
} ti_speech_bank;

A table of phrases and, optionally, the phrase numbers of the thirty number words: zero to nineteen, twenty to ninety, hundred and thousand. tools/speech.py generates the whole bank; --no-numbers leaves the number words out and sets number_ids to NULL. The bank and everything it points to stay borrowed until another bind or audio shutdown.

Functions

ti_speech_bind

ti_error ti_speech_bind(const ti_speech_bank *bank);

Checks the bank and makes it current, cancelling any speech in progress. Binding works before ti_audio_init too.

Returns

TI_OK; TI_E_ARGUMENT for an unreadable bank, phrase table or number table, or zero phrases; TI_E_RANGE for an empty or unreadable phrase, or a number word that is not a phrase of the bank.

ti_speech_say

ti_error ti_speech_say(uint8_t phrase, uint8_t priority);

Queues phrase number phrase of the bound bank, or starts it at once with TI_SPEECH_INTERRUPT. The call returns immediately; speech advances in ti_audio_update.

Returns

TI_OKQueued or started.
TI_E_RANGENo bank is bound, or the phrase number is not below the bank's count.
TI_E_UNAVAILABLEAudio is not running, speech is not enabled, or speech timed out earlier and is off until audio is started again.
TI_E_BUSYAn interrupting phrase with a lower priority than the one speaking.
TI_E_FULLFour items are already waiting.

ti_speech_number

ti_error ti_speech_number(uint16_t value, uint8_t priority);

Queues a number as ordinary cardinal English without "and": 1001 is "one thousand one", 1984 "one thousand nine hundred eighty four". It joins at most six words into one queue item. This code is a separate archive module, linked only by programs that call it.

Returns

As ti_speech_say, with TI_E_STATE when no bank is bound, TI_E_RANGE above 9999 and TI_E_UNAVAILABLE when the bank has no number words.

ti_speech_busy

uint8_t ti_speech_busy(void);

Nonzero while a phrase is speaking or waiting. A game can skip a minor line when another is still playing: if (!ti_speech_busy()) ti_speech_say(SAY_POWER, 1);

ti_speech_stop

void ti_speech_stop(void);

Cancels the current and waiting phrases and powers the SSI-263 down.

ti_speech_voice

ti_error ti_speech_voice(uint8_t preset, uint8_t pitch, uint8_t rate);

Cancels pending speech and sets the voice: preset 0-2 chooses one of three articulation and amplitude settings, pitch is the SSI-263 inflection value, and rate 0-15 goes into the chip's rate field. Audio init uses preset 0, pitch 0x40 and rate 10. The chip stays powered down until the next phrase.

Returns

TI_OK; TI_E_UNAVAILABLE when audio is not running or speech is not enabled; TI_E_ARGUMENT for a preset above 2 or a rate above 15.

How the driver talks to the SSI-263

  • On a native Phasor, the interrupt handler notes the chip's completion signal and acknowledges it by rewriting the inflection register, which does not change the phoneme.
  • On a Mockingboard, the driver polls the VIA's CA1 flag; its interrupt stays disabled. SSI writes share the first VIA's port with the first AY chip, so after each one the driver restores the port setup and resends that chip's registers. AY writes use the no-handshake port register so they do not clear CA1.
  • A phoneme that does not report completion within two seconds of device ticks powers speech down, cancels the queue and makes ti_audio_update return TI_E_TIMING once. Later speech calls return TI_E_UNAVAILABLE until audio is shut down and started again. Music and effects carry on.

The SSI-263 needs a clock from the Appletini. The F1.3.2 baseline clocks both speech engines from the virtual PHI0 in standalone ONE//e mode. F1.3.1 clocked them only from the physical Q3 pin, which no motherboard drives in that mode: the chip never started a phoneme, the first phrase timed out after two seconds and speech was then off, while music, effects and the VIA clock kept working. examples/speech_check shows the condition on a board. libtini needed no change for F1.3.2. Configured speech is an attempt, not a claim that a chip is present; keep essential messages on screen as captions.
