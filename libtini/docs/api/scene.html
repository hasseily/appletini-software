Sprite scenes

#include "libtini/scene.h"

A band renderer for games that move many small sprites over a plain background. Each frame the game lists its sprites; ti_scene_draw rebuilds and publishes only the parts of one screen rectangle that changed since the last draw.

NamePurpose
TI_SCENE_STORAGEDefine the sprite list and composition strip, once per program
ti_scene_beginStart a scene on a screen rectangle
ti_scene_frameStart the next frame's sprite list
ti_scene_addAppend a sprite, in draw order
ti_scene_drawCompose and publish every changed block
ti_scene_forgetThe area now shows only the background
ti_scene_invalidateRedraw the whole area at the next draw

How a scene draws

The scene divides its rectangle into blocks of 16 pixels (8 bytes) by 8 lines. ti_scene_add compares each sprite with the one at the same position in the previous list. An identical sprite costs nothing. A sprite that moved, changed image or colour, or disappeared marks the blocks it covered and the blocks it now covers.

For every 8-line band that holds marked blocks, ti_scene_draw fills those blocks of an 8-line near strip with the background colour, draws every listed sprite that reaches the band in list order, and publishes each run of adjacent marked blocks with ordinary CPU writes. An unchanged list publishes nothing. No banked surface is involved, and the draw needs an active video session.

The scene has no image of what else is on the screen. It assumes its rectangle shows only the background and its own sprites. When something else draws there, tell it with ti_scene_forget or ti_scene_invalidate.

Types and storage

ti_image

typedef struct ti_image { const uint8_t *pixels; uint8_t row_bytes, rows, stride; } ti_image;

A sprite image in near memory: packed 4-bit pixels, two per byte, high nibble first, colour 0 transparent. row_bytes is the width in bytes (two pixels each), rows the height, stride the bytes from one row to the next, so an image can sit inside a larger sheet. pixels NULL makes a solid rectangle 2 * row_bytes by rows pixels in the colour given to ti_scene_add; its stride is ignored.

ti_scene_config

typedef struct ti_scene_config {
    uint16_t x, y, width, height;  /* screen pixels: x and width even, height a multiple of 8 */
    const ti_image *images;        /* near, borrowed until the next begin */
    uint8_t image_count;
    uint8_t background;            /* colour 0..15 under every sprite */
    void (*service)(void);         /* called after every fourth band while drawing, or NULL */
} ti_scene_config;
x, y, width, height
The screen rectangle. x and width are even, height is a nonzero multiple of 8, and the rectangle lies within 320x200. width is at most 2 * row_bytes of the storage.
images, image_count
The image table, 1-255 entries. Sprites name images by index.
background
The colour of the area under all sprites.
service
Called after bands 4, 8, 12 and so on of every draw, changed or not. Use it to call ti_audio_update so a long draw does not starve the music. It must not call scene functions or draw in the area.

TI_SCENE_STORAGE

#define TI_SCENE_STORAGE(sprites, row_bytes) ...

Defines the sprite list and the composition strip as global variables, which the renderer reaches at fixed addresses. Use it exactly once in a program, at file scope. sprites is the list capacity, 1-255; row_bytes the widest area in bytes. It costs 8 bytes per sprite plus 8 * row_bytes for the strip, in BSS, or in the near arena when placed between #pragma bss-name (push, "NEARBSS") and #pragma bss-name (pop).

TI_SCENE_STORAGE(64, 120);   /* 64 sprites a frame, areas up to 240 pixels wide:
                                 512 + 960 bytes */

Functions

ti_scene_begin

ti_error ti_scene_begin(const ti_scene_config *config);

Starts a scene. The configuration is copied; the image table and pixels stay borrowed until the next ti_scene_begin. Every image is checked once here: nonzero row_bytes and rows, and for images with pixels a stride of at least row_bytes and (rows - 1) * stride + row_bytes readable near bytes. The list starts empty and the area is taken to show only the background; call ti_scene_invalidate when it does not. A video session is not needed to begin, only to draw.

Returns

TI_OK; TI_E_ARGUMENT for a missing or unreadable configuration or image table, or zero images; TI_E_RANGE for a bad area, a background above 15 or a bad image. After an error no scene is active.

ti_scene_frame

void ti_scene_frame(void);

Starts the next frame's list. The last drawn list is kept for comparison, so sprites that moved, changed or went away are erased by the next draw.

ti_scene_add

ti_error ti_scene_add(int16_t x, int16_t y, uint8_t image, uint8_t color);

Appends a sprite with its top-left corner at screen position x, y. Later sprites cover earlier ones. Positions are signed and sprites are clipped to the area. An odd x is rounded down: sprites sit on whole bytes. color is used only by rectangle images.

The comparison is by list position, so keep each object at a stable index from frame to frame. Pixels changed inside an image are not noticed; switch to another image index or call ti_scene_invalidate.

Returns

TI_OK; TI_E_FULL when the list holds its capacity (the sprite is dropped); TI_E_RANGE for an image index not below image_count; TI_E_STATE before ti_scene_begin.

ti_scene_draw

ti_error ti_scene_draw(void);

Erases sprites past the new list's end, composes every band with marked blocks and publishes them, calling service after every fourth band. Draws do not use ti_gfx_budget or statistics: the list capacity and the area bound the work.

Returns

TI_OK, or TI_E_STATE without an active scene and video session, before any write.

ti_scene_forget

void ti_scene_forget(void);

Something else drew over the area and left only the background there, such as publishing a canvas that is clear in the area. Nothing of the last list is on screen any more: the next draw draws every listed sprite and erases nothing.

ti_scene_invalidate

void ti_scene_invalidate(void);

The area shows something other than the background and the last list. The next draw redraws the whole area, background included.

Example

#include "libtini.h"

TI_SCENE_STORAGE(64, 120);                  /* 64 sprites, areas up to 240 pixels wide */
extern const uint8_t ship[], sheet[];        /* packed pixels, colour 0 transparent */
extern int16_t ship_x, ship_y, shot_x[], shot_y[];   /* the game's state */
extern uint8_t shots;

static void service(void) { ti_audio_update(); }

static const ti_image images[] = {
    {ship, 8, 16, 8},                         /* 16x16 */
    {sheet + 4, 2, 4, 16},                    /* 4x4 inside a 32-pixel-wide sheet */
    {0, 1, 2, 0},                             /* a 2x2 rectangle in the sprite's colour */
};
static const ti_scene_config scene = {0, 16, 240, 184, images, 3, 0, service};

void play(void)
{
    uint8_t i;
    ti_scene_begin(&scene);
    for (;;) {
        /* ... update the game ... */
        ti_scene_frame();
        ti_scene_add(ship_x, ship_y, 0, 0);
        for (i = 0; i < shots; ++i) ti_scene_add(shot_x[i], shot_y[i], 2, 15);
        ti_scene_draw();
    }
}

Costs

The renderer adds 2,042 bytes of code and constants and 197 bytes of state to a program, besides the storage that TI_SCENE_STORAGE defines. Its work grows with the number of marked blocks and with the sprites that reach marked bands. When STARFALL moved its 240x184 playfield to this renderer, listing and drawing took about 14-16 ms a frame on the emulator's 33 MHz model, against 22.5-23.6 ms for the game's own earlier renderer. Its later parallax backdrop of 24 more sprites adds about 6 ms. These are model figures, not board timing.

Defined in include/libtini/scene.h, implemented in src/scene.c and src/target/scene.s.
