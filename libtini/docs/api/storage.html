libtini

Storage

#include "libtini/storage.h"

Whole-file ProDOS reads and writes into near memory, and resource packs loaded into banked memory. Calls use the standard ProDOS MLI at $BF00; no private SmartPort service is involved.

FunctionPurpose
ti_file_readRead a whole file into a near buffer
ti_file_writeCreate or replace a file from a near buffer
ti_file_last_errorThe ProDOS error behind the last failure
ti_pack_loadLoad one entry of a TPK1 pack into a new resource

How file calls work

  • Every call is synchronous and foreground-only, and handles one file: it opens, transfers and closes before returning. A call made while another runs returns TI_E_BUSY before opening anything.
  • Names are relative to the current ProDOS prefix: 1-15 characters, a capital letter first, then capitals, digits or periods. Paths, lower case and underscores are rejected with TI_E_ARGUMENT.
  • ProDOS needs a 1 KiB I/O buffer at a page boundary. The shared layouts reserve MAIN $B000-$B3FF for it under the linker symbol _ti_file_buffer; do not use those bytes. A layout that leaves the symbol out gives that memory to the game, and then no file call links. See memory and layouts.
  • The audio driver pauses while ProDOS owns the machine: music mutes, effects and speech are cancelled, and the clock stops instead of counting the pause as game time.
  • Standard ProDOS can keep its /RAM disk in the same AUX bank 0 bytes as the SHR picture. During a video session each call saves the picture into a temporary resource, turns SHR off, puts the OS's own bytes back, calls ProDOS, captures any change ProDOS made, restores the picture and turns SHR on again. That needs a free slot and 32,768 resource bytes; without them the call returns TI_E_NOMEM before any ProDOS call. Outside a session no resource is needed and file calls work without ti_init.
  • Only TI_OK means the transaction completed. After an error, discard any data the call returned. A failed write can leave a changed or partial file: keep two save slots and validate them, as Saved games shows.

Functions

ti_file_read

ti_error ti_file_read(const char *name, void *dst, uint16_t capacity, uint16_t *length);

Reads the whole file into dst and stores its size in *length. A file larger than capacity is not read at all. An empty file may use a NULL buffer with zero capacity.

Returns

TI_OKThe whole file is in dst.
TI_E_ARGUMENTlength is not writable near memory, or the name is invalid.
TI_E_RANGEdst is not writable near memory for capacity bytes, or the file is larger than capacity.
TI_E_BUSYAnother storage call is running.
TI_E_NOMEMDuring a video session, no room for the screen loan.
TI_E_IOProDOS failed to open, size, read or close the file; see ti_file_last_error.

*length is 0 unless the call succeeds.

ti_file_write

ti_error ti_file_write(const char *name, const void *src, uint16_t length);

Creates the file as a binary file (ProDOS type $06) if it does not exist, writes length bytes, sets the end of file to exactly length and closes it, which flushes the data and directory. Writing fewer bytes than the old file held truncates it; a zero length leaves an empty file.

Returns

TI_OK; TI_E_RANGE when src is not readable near memory for length bytes; TI_E_ARGUMENT for an invalid name; TI_E_BUSY; TI_E_NOMEM as above; TI_E_IO when a ProDOS create, open, write, set-EOF or close fails.

ti_file_last_error

uint8_t ti_file_last_error(void);

The ProDOS MLI error code of the last failed call, or 0 after a successful one. An unexpectedly short read or write records $4C. Argument, range and memory errors leave no new ProDOS code; read the byte together with the call's result.

CodeProDOS meaning
$27I/O error
$2BDisk write-protected
$40Invalid pathname
$44Path not found
$45Volume not found
$46File not found
$48Volume full
$49Volume directory full
$4CEnd of file encountered
$4EAccess error, such as a locked file

ti_pack_load

ti_error ti_pack_load(const char *name, const char *entry,
                      ti_handle *out, uint32_t *size);

Opens the TPK1 pack name, validates its whole directory, allocates one resource of the entry's size and streams the entry's bytes into it in 128-byte pieces. On success the caller owns the handle and frees it with ti_res_free. On any error the file is closed, a partly loaded resource is freed and both outputs are zero.

Entry names are 1-15 characters: a capital letter, then capitals, digits, periods or underscores. File names keep ProDOS's narrower rule. The loader does not interpret the entry: read its TI4, TIF or TIM header yourself and make the surface, font or map view, as Art, fonts, maps and packs shows. A pack needs an active ti_init grant.

Returns

TI_OK*out owns a resource of *size bytes.
TI_E_ARGUMENTUnwritable outputs, or an invalid file or entry name.
TI_E_UNAVAILABLEThe pack has no such entry.
TI_E_FORMATThe directory is malformed: bad header, count, names, order, offsets or sizes. Unselected entries are checked too.
TI_E_NOMEM, TI_E_STATENo slot or room for the entry or the screen loan, or no ti_init.
TI_E_IOA ProDOS open, read, seek or close failed.
TI_E_BUSYAnother storage call is running.
ti_handle art;
uint32_t bytes;
if (ti_pack_load("RESOURCES.TPK", "SHIP", &art, &bytes) != TI_OK) return;
/* ... make views of art; ti_res_free(art) when done ... */

The pack format is in Data formats. tools/assets.py pack writes packs; the repository's disk packager stores files of up to 131,072 bytes, so larger packs need another ProDOS tool even though the loader can stream them.

Defined in include/libtini/storage.h, implemented in src/storage.c and src/target/storage.s.
