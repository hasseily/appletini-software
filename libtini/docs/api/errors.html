libtini

Types and errors

#include "libtini/types.h"

Result codes, handles and a way to collect the first failure of a frame. Every other header includes this one; libtini.h includes them all.

Language and calling convention

The headers target cc65 2.19's C99 subset on the 65C02 with cc65's default ABI: non-variadic functions use __fastcall__, with the last argument in A/X/sreg and earlier ones on the C stack. Public widths come from stdint.h. No public enum has an ABI-sized type: codes are macros of fixed-width types.

Types

ti_error

typedef uint8_t ti_error;

The result of every call that can fail. TI_OK is zero, so if (ti_init(1, 3)) tests for failure.

ti_handle

typedef uint16_t ti_handle;
#define TI_INVALID_HANDLE ((ti_handle)0)

A banked resource. The value encodes a resource slot and a generation, never an address. TI_INVALID_HANDLE is never a live handle; ti_res_alloc stores it when allocation fails.

Result codes

ValueNameMeaning
0TI_OKThe call completed.
1TI_E_ARGUMENTAn argument the call cannot use: a NULL or unreadable structure pointer, a zero size, a colour above 15, an invalid file name.
2TI_E_STATEThe wrong moment in a lifecycle: the module is not started, already started, or needs a video session or scene that is not active.
3TI_E_RANGEA position, offset, length or value outside its bound, including a near buffer that leaves its permitted region and a resource range past its end.
4TI_E_NOMEMNo free resource slot or no room in the granted banks; also a full keyboard queue.
5TI_E_HANDLEA handle that was freed, belongs to an earlier ti_init, or was never valid.
6TI_E_UNAVAILABLEA device or service that is absent or not supported, found before anything was changed. Also an empty key queue, a missing pack entry and spoken numbers without a number table.
7TI_E_TIMINGA clock gap, a timeout, a publication over its byte budget or measured deadline, or a paddle that did not finish.
8TI_E_BUSYAn ownership or priority conflict, a call made while another is in progress, or a measurement that interrupts disturbed.
9TI_E_IOA ProDOS or transport failure. After a submitted AMEM transfer fails, the destination may be partly changed.
10TI_E_FORMATInvalid authored data, such as a malformed resource pack.
11TI_E_FULLA bounded queue or list is full: the speech queue or a scene's sprite list.

Each function's entry in this reference lists the codes it returns and why. The same code can mean slightly different things in different modules; the entry is the authority.

Collecting the first error

These three calls let a game handle failures once a frame instead of after every call. Only results passed to ti_error_keep are kept.

for (;;) {
    ti_error_keep(ti_gfx_text_opaque(&canvas, 250, 64, score_text, 9, 0));
    ti_error_keep(ti_gfx_present(&canvas, &score_box, 0));
    ti_error_keep(ti_scene_draw());
    if (ti_error_first()) break;        /* stop on the first failure */
}
show_error_code(ti_error_first());

ti_error_keep

ti_error ti_error_keep(ti_error e);

Returns e unchanged. If no error is kept yet and e is nonzero, keeps e. Because it returns its argument, it can wrap a call inside a test: if (ti_error_keep(ti_init(1, 3))) goto done;

ti_error_first

ti_error ti_error_first(void);

The first nonzero result passed to ti_error_keep since the program started or since ti_error_clear; TI_OK if there is none.

ti_error_clear

void ti_error_clear(void);

Forgets the kept error, so the next failure passed to ti_error_keep is kept.

Defined in include/libtini/types.h, implemented in src/error.c.
