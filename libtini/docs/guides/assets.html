Art, fonts, maps and packs

Convert art to SHR's packed format on the host, put it in a resource pack on the game disk, load it into banked memory and point surfaces, fonts and maps at it. Scene sprites take the other route: near C arrays compiled into the program.

The palette

Every converted image is matched against one shared palette, a JSON list of up to sixteen colours as 0RGB integers or "#RRGGBB" strings. Missing entries are 0. A #RRGGBB colour keeps the high four bits of each channel.

["#000000", "#FFFFFF", "#FF0000", "#00C000", 255, 4095]

Plan the palette with the game: entry 0 is the transparent colour of keyed sprites and masks, and entries the art never uses are free for palette animation.

Images

python tools/assets.py image ship.ppm ship.ti4 --palette palette.json --palette-output palette.bin --masked --report ship-layout.json
python tools/assets.py indexed ship.json ship.ti4
  • image reads a P3 or P6 PPM with 8-bit channels, 1-320 by 1-200 pixels, and maps each pixel to the nearest palette entry. --palette-output also writes the sixteen palette words, ready for ti_gfx_begin.
  • indexed reads JSON with width, height, row-major pixels of 0-15 and optional "masked": true.
  • --masked appends a one-bit opacity mask in which index 0 is transparent, for ti_gfx_sprite.
  • The output is a TI4 file: an 8-byte header with the width and height, then packed rows, then the mask. Data formats has the bytes.

The tool uses only Python's standard library and writes no timestamps, so the same input always gives the same bytes. Convert PNG art to PPM with any image editor first; STARFALL's own generator, tools/starfall_assets.py, shows how to read indexed PNGs directly.

Fonts

{"width": 5, "height": 7, "first": 65, "glyphs": [
  [".###.", "#...#", "#...#", "#####", "#...#", "#...#", "#...#"],
  ["####.", "#...#", "#...#", "####.", "#...#", "#...#", "####."]
]}
python tools/assets.py font font.json font.tif

Glyphs are at most 8 by 16 pixels, written as height strings of width dots and hashes. first is the character code of the first glyph, 32 when omitted. The built-in 5x7 font needs no file.

Tile maps

{"rows": [[0, 1, 1, 0], [2, 3, 3, 2]], "tile_count": 4}
python tools/assets.py map level.json level.tim

A map is 1-256 rows of 1-256 tile numbers, all rows the same length. With tile_count, larger numbers are rejected. The tile atlas is an ordinary image.

Resource packs

A pack holds up to sixteen named entries in one ProDOS file, so a game opens one file for all its banked art. Its manifest names each entry and the file it comes from:

{"entries": [
  {"name": "SHIP", "path": "ship.ti4"},
  {"name": "FONT", "path": "font.tif"},
  {"name": "LEVEL1", "path": "level.tim"}
]}
python tools/assets.py pack pack.json RESOURCES.TPK --report resources-layout.json

Entry names are unique, 1-15 bytes: a capital letter, then capitals, digits, periods or underscores. Each entry is 1 byte to 4 MiB, and the whole pack must fit ProDOS's 24-bit file size. Entry paths are relative to the manifest and must be ordinary files inside its folder; links and paths outside it are rejected. The report gives the pack's size and the least number of 48,640-byte banks it needs. It does not count the screen backup or any other allocation.

Keep the converted files and the pack manifest together in one folder of the game, and let the build make the pack and put it on the disk:

"generate": [
  {"command": ["{root}/tools/assets.py", "pack", "{game}/art/pack.json", "{build}/RESOURCES.TPK"],
   "inputs": ["{root}/tools/assets.py", "art"],
   "outputs": ["{build}/RESOURCES.TPK"]}
],
"disk": {"volume": "MYGAME", "system": "MYGAME.SYSTEM",
         "files": [{"name": "RESOURCES.TPK", "path": "{build}/RESOURCES.TPK"}]}

The disk packager stores files of up to 131,072 bytes.

Load an entry and make views

ti_pack_load copies one entry into a new resource and hands you its handle. The loader does not interpret the bytes: read the 8-byte header and fill in a surface, sprite, font or map that points into the resource at offset 8. These structures are borrowed views; free the entry's handle with ti_res_free when every view is finished, and never call ti_gfx_surface_free on a view.

static uint16_t le16(const uint8_t *p) { return p[0] | (uint16_t)p[1] << 8; }

/* A TI4 entry as a surface. */
static ti_error image_view(ti_handle entry, ti_surface *view)
{
    uint8_t h[8];
    ti_error e = ti_res_read(entry, 0, h, 8);
    if (e) return e;
    if (h[0] != 'T' || h[1] != 'I' || h[2] != '4' || h[3]) return TI_E_FORMAT;
    view->pixels = entry;
    view->offset = 8;
    view->width = le16(h + 4);
    view->height = le16(h + 6);
    view->stride = (view->width + 1) / 2;
    return TI_OK;
}

static ti_handle ship_entry, font_entry, map_entry;
static ti_sprite ship;
static ti_bitmap_font font;
static ti_tilemap map;

ti_error load_art(void)
{
    uint8_t h[8];
    uint32_t size;
    ti_error e = ti_pack_load("RESOURCES.TPK", "SHIP", &ship_entry, &size);
    if (!e) e = image_view(ship_entry, &ship.image);
    if (e) return e;
    ship.mask = ship_entry;                        /* converted with --masked */
    ship.mask_offset = 8 + (uint32_t)ship.image.stride * ship.image.height;

    e = ti_pack_load("RESOURCES.TPK", "FONT", &font_entry, &size);
    if (!e) e = ti_res_read(font_entry, 0, h, 8);   /* "TIF1", first, count, width, height */
    if (e) return e;
    font.glyphs = font_entry; font.offset = 8;
    font.first = h[4]; font.count = h[5]; font.width = h[6]; font.height = h[7];

    e = ti_pack_load("RESOURCES.TPK", "LEVEL1", &map_entry, &size);
    if (!e) e = ti_res_read(map_entry, 0, h, 8);    /* "TIM1", columns, rows */
    if (e) return e;
    map.cells = map_entry; map.offset = 8;
    map.columns = le16(h + 4); map.rows = le16(h + 6);
    return TI_OK;
}

Each ti_pack_load opens the file and checks the whole directory again; that is fine at a level change. Every entry takes one of the eight resource slots, so combine small images into one atlas and use source rectangles instead of loading many entries.

A tile set is an image view plus the tile size:

ti_tileset tiles;
image_view(atlas_entry, &tiles.image);
tiles.tile_width = 16; tiles.tile_height = 16;
tiles.columns = (uint8_t)(tiles.image.width / 16);
tiles.count = 40;

Sprites for a scene

Scene images are near memory: an array of packed bytes, two pixels each, high nibble on the left, colour 0 transparent. A small one can be written by hand:

/* A 4x4 orb: colour 15 rim, colour 14 core. */
static const uint8_t orb[] = {
    0x0F, 0xF0,
    0xFE, 0xEF,
    0xFE, 0xEF,
    0x0F, 0xF0
};
static const ti_image images[] = {
    {orb, 2, 4, 2},          /* row_bytes, rows, stride */
};

For real art, generate a header in a manifest generate step. STARFALL's tools/starfall_assets.py reads its archive's PNGs, packs sixteen 16x16 cells and writes their bytes, the palette and a table of sub-sprites inside one cell; its scene table then names each cell as an image of 8 bytes by 16 rows, and the small images inside one cell with that cell's 8-byte stride. Constant arrays go to the RODATA segment, which the full-game layout runs from low memory at $0800-$1FFF, leaving main memory for code and state.
