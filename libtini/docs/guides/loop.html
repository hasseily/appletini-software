Game loop and timing

Simulate at a fixed rate from the audio device clock, draw only when something is due, keep the music serviced during long work and pause cleanly when time cannot be trusted.

The shape of a loop

The game owns its loop. libtini gives it a clock that runs at the same rate at 33 MHz and in TURBO, and turns that clock into a number of simulation steps. The simulation then advances by fixed steps, while drawing happens as often as the machine allows.

#include "libtini.h"

/* The game's own parts. */
ti_error start_screen(void);
void pause_game(void);
uint8_t read_controls(void);
void update_game(uint8_t controls);
void draw_changes(void);

/* Mockingboard, no speech, nominal clock, one AY chip of three voices. */
static ti_audio_config audio = {TI_AUDIO_MOCKINGBOARD, 0, 0, 0, 3};

int main(void)
{
    uint8_t steps, key, controls;
    if (ti_init(1, 3)) return 1;
    if (start_screen()) return 1;          /* surface, ti_gfx_begin, first frame */
    if (ti_audio_init(&audio)) return 1;  /* the clock comes from the card */
    ti_steps_begin(ti_audio_ticks, TI_AUDIO_TICKS_PER_SECOND, 30, 30);
    for (;;) {
        ti_audio_update();                 /* music, effects and speech */
        ti_input_poll();
        if (ti_input_key(&key) == TI_OK && (key == 'Q' || key == 'q')) break;
        if (!ti_audio_clock_valid()) { pause_game(); continue; }
        steps = ti_steps_due();
        if (steps == TI_STEPS_GAP) { pause_game(); continue; }
        if (!steps) continue;              /* nothing due: nothing to draw */
        controls = read_controls();        /* ti_input_held, ti_stick_read */
        while (steps--) update_game(controls);
        draw_changes();                    /* scene and HUD; see Drawing */
        if (ti_error_first()) break;
    }
    return 0;                              /* cleanup runs on return */
}
  • ti_steps_begin(ti_audio_ticks, TI_AUDIO_TICKS_PER_SECOND, 30, 30) asks for 30 updates a second from the nominal 100 Hz clock. The remainder of a step carries over, so an update falls due every 3 or 4 ticks and the average stays exactly 30 a second.
  • The last argument caps one call at 30 steps. Time beyond the cap is dropped: after a very slow frame the game slows down instead of jumping ahead. Use a smaller cap, such as 4, when catching up a whole second at once would be unfair to the player.
  • Controls are read once per drawn frame and applied to every step of that frame.
  • The loop draws only after it ran at least one step, so a fast frame does not redraw an unchanged screen.

Pausing and gaps

Two things mean the clock cannot be trusted for the moment: ti_steps_due returns TI_STEPS_GAP when more than a second passed between calls, and ti_audio_clock_valid turns 0 when the audio driver detects a gap: more than a second between updates, or more than 32 score events or song rows due at once. A game should pause then, as STARFALL does, instead of simulating a second it did not see.

void pause_game(void)
{
    uint8_t key;
    ti_music_stop();
    show_pause_panel();
    do ti_input_poll(); while (ti_input_key(&key) != TI_OK);
    ti_audio_resume_clock();   /* re-arm the clock after a gap; harmless otherwise */
    ti_steps_reset();          /* the paused time is not game time */
    redraw_screen();
    start_music();
}

ti_steps_due keeps only the low 16 bits of the clock. A pause that can last 65,536 ticks or more, about eleven minutes, must end with ti_steps_reset, as above.

Keep the music going

ti_audio_update plays the score events and song rows that came due since its last call, and writes the AY registers once a tick. It catches up to 32 events or rows; more than that, or more than 100 ticks between calls, stops the music with TI_E_TIMING. Call it at least once a tick, every 10 ms, for even music. Long work needs extra calls:

  • A sprite scene calls its configuration's service function after every fourth 8-line band. Point it at a function that calls ti_audio_update.
  • Between drawing calls, call ti_audio_update yourself. STARFALL's present helper calls it after each publication, and its large title logo calls it after each letter.
  • Calls within one tick do almost nothing, so extra calls are cheap.
static void service(void) { ti_audio_update(); }
static const ti_scene_config scene = {0, 16, 240, 184, images, IMAGE_COUNT, 0, service};

Blocking work

File calls and AMEM requests pause the audio driver themselves: the clock stops, effects and speech are cancelled and music mutes, then everything resumes and the paused time does not count. For other work that blocks or keeps interrupts masked for more than a tick, do the same:

ti_audio_mark_gap();        /* silence, stop the clock */
long_blocking_work();
ti_audio_resume_clock();    /* rebase; the gap is not elapsed time */
ti_steps_reset();

Animation by ticks

Animate with elapsed device ticks or simulation steps, not with drawn frames, so animations keep their speed when drawing slows. ti_gfx_animation_frame does the arithmetic for a frame run; palette animation, STARFALL's pulsing bullets and shields, needs only a new palette from the step counter and one ti_gfx_palette call a frame.

Errors once a frame

Wrap drawing and other calls whose failure should end the game in ti_error_keep and test ti_error_first once a frame. Do not keep the result of ti_audio_update: it reports gaps and speech timeouts, which a game handles by pausing or by playing on without speech.

Display edges are not a clock

ti_time_poll counts the vertical blank edges it happens to see. The count is a lower bound and stops whenever the game is busy, so it cannot time a game. libtini has no wait-for-vertical-blank call either: publication finishes when its CPU writes do, and the Appletini shows the screen at its own frame boundary.
