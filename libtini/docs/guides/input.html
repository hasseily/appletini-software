Keyboard and joystick

Commands from key events, movement from the held key and the joystick, and buttons with press detection. All of it reads the standard //e inputs; the joystick needs the audio driver for its timer.

Two kinds of keyboard input

The //e keyboard reports characters, one at a time, and whether any key is down. It has no release events and no matrix of keys. libtini gives two views of it:

  • Key events for commands and menus: ti_input_poll moves each new keypress into an eight-character queue, and ti_input_key takes them out in order.
  • The held key for movement: ti_input_held returns the newest key while any key is down, or 0. Hold A, tap Space, and it returns Space until every key is up, so two held directions cannot make a diagonal; use the joystick for that.

Move while a key is held

A held key moves the player every update. A tap shorter than one drawn frame can come and go between two reads of the held key, so STARFALL also takes the direction from key events and keeps it for one frame. Arrow keys arrive as control codes: left 8, right 21, up 11, down 10.

#define UP 1
#define DOWN 2
#define LEFT 4
#define RIGHT 8
static const char move_key[8] = {'W', 11, 'S', 10, 'A', 8, 'D', 21};
static const uint8_t move_dir[8] = {UP, UP, DOWN, DOWN, LEFT, LEFT, RIGHT, RIGHT};
static uint8_t direction, tapped;

static uint8_t direction_of(uint8_t k)
{
    uint8_t i;
    if (k >= 'a' && k <= 'z') k -= 32;
    for (i = 0; i < sizeof(move_key); ++i) if (k == move_key[i]) return move_dir[i];
    return 0;
}

/* Once a frame, after ti_input_poll(). */
static void read_keys(void)
{
    uint8_t key, d;
    while (ti_input_key(&key) == TI_OK) {
        if ((d = direction_of(key)) != 0) { direction = d; tapped = 1; }
        else handle_command(key);        /* pause, quit, bomb ... */
    }
    key = ti_input_held();
    if (key) { if ((d = direction_of(key)) != 0) direction = d; }
    else if (!tapped) direction = 0;    /* released, and no tap this frame */
    tapped = 0;
}

The joystick

ti_stick_read returns TI_STICK_UP, DOWN, LEFT and RIGHT bits, diagonals included, measured against the stick's own rest position. Real Apple joysticks rarely rest at 128 or travel the same distance each way, so the reader learns both:

  • It takes the first reading within 48-207 on both axes as the rest. Call ti_stick_recalibrate whenever the stick should be untouched, such as when a run starts, a game resumes or the player turns the stick back on.
  • A direction engages beyond a third of the furthest travel seen on that side, at least 16 units, and releases at three quarters of that, so a stick held near the edge does not flicker.
  • With no stick, the reader returns TI_STICK_ABSENT; after four such reads it waits three seconds before measuring again, so an empty port costs little.

The starter and STARFALL combine stick and keys. A deflected stick wins; a stick at rest leaves the keys in charge, so both can stay connected:

uint8_t stick = stick_enabled ? ti_stick_read(0) : TI_STICK_ABSENT;
uint8_t input;
read_keys();
if (stick != TI_STICK_ABSENT && stick) input = stick;   /* deflected */
else input = direction;                                  /* keys */

Give players a key that turns the stick off (STARFALL uses J): a stick that drifts badly would otherwise keep overriding the keys.

Buttons

ti_input_buttons returns the three button inputs as bits 0-2; the joystick's two buttons are the Open and Solid Apple inputs, bits 0 and 1. Detect a press by comparing with the last reading:

static uint8_t last_buttons;
uint8_t now = ti_input_buttons() & 3;
uint8_t pressed = now && !last_buttons;
last_buttons = now;
if (pressed) drop_bomb();

A player may still be holding a button when the game changes state, such as when the ship is lost. Ignore presses for a moment then: STARFALL accepts a retry only one second after the ship is lost.

Raw readings

ti_joystick_read returns both paddles as 0-255 with the buttons. Use it for analog control or for a screen that shows what the stick reports; STARFALL's pause panel prints JOY x y so a player can check a stick. A paddle still running after 4 ms reads 255 and the call returns TI_E_TIMING; a read that interrupts disturbed returns TI_E_BUSY and leaves the old values, so try again next frame.

ti_joystick j;
if (ti_joystick_read(&j) != TI_E_BUSY) show_stick(j.x, j.y);

Why paddle reads wait

On the //e, any access to $C070-$C07F starts the paddle timers, including the RamWorks bank selector at $C073, and a 558 timer that is still running ignores a new start. A read started too soon after such an access would measure from the earlier start and come out short; on a stick that shows up as right and down readings jumping back. libtini avoids writing the selector for bank 0 transfers, which include all screen publication, and every read waits up to 4 ms for running timers to finish. Do not touch $C070-$C07F yourself between reads.
