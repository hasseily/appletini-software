Saved games

A ProDOS write is not atomic: power loss or a disk error can leave a half-written file. Write saves to two files in turn and load the newer one that checks out.

Two slots

  • Keep the save in one small structure with a marker, a sequence number and a checksum.
  • Each save goes to the file that does not hold the newest good save, so a failed write never destroys the last good one.
  • Loading reads both files, discards any that is short, has the wrong marker or fails its checksum, and keeps the one with the newer sequence number.
#include "libtini.h"

#define SAVE_MAGIC 0x5A
typedef struct save_data {
    uint8_t magic, sequence;
    uint32_t best_score;
    uint8_t level, checksum;            /* checksum stays last */
} save_data;

static save_data current;
static const char *const slot_name[2] = {"SAVE.A", "SAVE.B"};
static uint8_t newest = 1;              /* the slot holding current; saves use the other */

static uint8_t checksum(const save_data *s)
{
    const uint8_t *p = (const uint8_t *)s;
    uint8_t i, sum = 0xA5;
    for (i = 0; i < sizeof(*s) - 1; ++i) sum = (uint8_t)((sum << 1 | sum >> 7) ^ p[i]);
    return sum;
}

/* Loads the newer valid slot into current; 0 when neither is valid. */
uint8_t load_game(void)
{
    save_data slot[2];
    uint16_t length;
    uint8_t i, valid[2];
    for (i = 0; i < 2; ++i)
        valid[i] = ti_file_read(slot_name[i], &slot[i], sizeof(slot[i]), &length) == TI_OK &&
                   length == sizeof(slot[i]) && slot[i].magic == SAVE_MAGIC &&
                   slot[i].checksum == checksum(&slot[i]);
    if (!valid[0] && !valid[1]) return 0;
    if (valid[0] && valid[1]) i = (int8_t)(slot[1].sequence - slot[0].sequence) > 0;
    else i = valid[1];
    current = slot[i];
    newest = i;
    return 1;
}

ti_error save_game(void)
{
    ti_error e;
    current.magic = SAVE_MAGIC;
    ++current.sequence;
    current.checksum = checksum(&current);
    e = ti_file_write(slot_name[newest ^ 1], &current, sizeof(current));
    if (e == TI_OK) newest ^= 1;
    return e;
}

The sequence comparison works across the wrap from 255 to 0. File names follow ProDOS's rule: a capital letter, then capitals, digits or periods, at most 15 characters, relative to the current prefix, which is normally the boot disk's volume.

What a file call needs

  • The file buffer. ProDOS needs the 1 KiB buffer at _ti_file_buffer, $B000-$B3FF in both shared layouts. A layout that leaves it out, as STARFALL's does, cannot link file calls at all.
  • Memory during a video session. With SHR on, each call lends AUX bank 0 back to ProDOS and keeps the picture in a temporary resource: one free slot and 32,768 bytes. Without them the call returns TI_E_NOMEM before ProDOS runs.
  • Nothing else in flight. Calls are synchronous; one made while another runs returns TI_E_BUSY.

Timing around a save

The audio driver pauses while ProDOS runs: music mutes, effects and speech stop, and the clock stops counting. When the call returns, the clock resumes without a gap and music continues. The picture is restored as it was. A save takes disk time, so do it at a natural pause, such as the game-over screen, and expect a moment of silence.

When a save fails

ti_file_write returns TI_E_IO for a ProDOS failure; ti_file_last_error gives ProDOS's code, such as $2B for a write-protected disk or $48 for a full volume. Tell the player in words, keep playing, and leave the other slot alone: it still holds the last good save.
