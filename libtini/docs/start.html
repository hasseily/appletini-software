libtini

Getting started

Install the compiler and the ProDOS input, build the library with its examples, boot a disk, then start a game of your own.

What you need

On the Apple

  • An enhanced Apple //e (65C02) with an Appletini. The selected firmware baseline is existing F1.3.2, commit 73de6fe03c31ad6f8ebfce3328704761fcd8c5a2; no firmware rebuild, flashing or slot change is needed.
  • RamWorks enabled. A game grants libtini a set of expansion banks (selectors) with ti_init; no RAM disk or other driver may use those banks. The diagnostic uses selectors 1-2, the starter and STARFALL use 1-3.
  • SmartPort in slot 7, which holds the boot disk.
  • A Mockingboard or Phasor personality in slot 4 for sound, speech, the game clock and the joystick timer.

Download cc65 2.19 from its release page. The build checks that all four cc65 programs report V2.19. Pass the SDK folder with --cc65-home, set CC65_HOME, or put the SDK's bin/ on PATH. The examples below use D:/Repos/cc65.

Build the library and examples

Run every command from the libtini/ folder of the repository.

python tools/setup_inputs.py
python tools/build.py --cc65-home D:/Repos/cc65

The first command downloads the official ProDOS 8 2.4.3 disk image once, checks its SHA-256 and stores it under build-inputs/prodos/, which git ignores. Every later build works offline. ProDOS is not redistributed by the repository; check its terms before you share a disk that contains it. --no-disk builds the programs and the library without ProDOS.

A build compiles the library, links every program and game, checks each linked layout and writes bootable disks:

The build ends with one memory line per game, such as:

starfall memory: LOW $0800-$1FFF 88 free; IMAGE $2000-$BEFF 1032 free; WORK $A26C-$B3FF 1110 free; NEAR $B480-$B6FF 1 free
starter memory: MAIN $2000-$9FFF 12321 free; NEAR $A900-$AEFF 1532 free

Run a disk

Boot build/starter.po from slot 7. Hold WASD or the arrow keys, or move a joystick, to move the square; a joystick button plays a tone and Q returns to ProDOS. The starter needs the slot-4 card: without it the screen says that a slot 4 audio card is required.

build/starfall.po starts STARFALL. Return or a joystick button launches with the Mockingboard, P with the Phasor. build/libtini.po runs five memory tests and shows PASS or FAIL for each; if the granted banks are missing or aliased it says so in text and still exits normally.

Start your own game

Inside this repository

A game is a folder under games/ or examples/ with a game.json manifest. The build finds every manifest by itself. Copy the starter's main.c into a new folder and add a manifest:

{
  "name": "mygame",
  "title": "MY GAME",
  "sources": ["main.c"],
  "disk": {"volume": "MYGAME", "system": "MYGAME.SYSTEM", "blocks": 280}
}
python tools/build.py --cc65-home D:/Repos/cc65 --game mygame

--game builds the library, the diagnostic and that one game. The outputs are build/mygame.system and build/mygame.po. Builds and game manifests describes every manifest key, generated assets and extra disk files.

As a separate project

python examples/starter/create.py C:/Projects/MyGame

This copies the runtime sources, public headers, the cfg/libtini.cfg layout and the disk tools into C:/Projects/MyGame/runtime/ as ordinary files, with the starter's main.c and a small build.py. The destination must not exist. SDK_INPUTS.json records the hash of every copied file. The project needs no checkout of this repository after that:

cd C:/Projects/MyGame
python runtime/tools/setup_inputs.py
python build.py --cc65-home D:/Repos/cc65

It builds build/APP.SYSTEM and build/APP.po. The copied runtime does not follow later SDK changes; create a new project, or copy the new sources, to pick them up. Do not patch the copies instead of changing the SDK source.

Read the starter

The starter is about a hundred lines and uses the calls most games need first: ti_init, a 320x200 surface, ti_gfx_begin, ti_audio_init for the clock, ti_steps_due for thirty updates a second, ti_input_held and ti_stick_read for movement, and ti_gfx_present for the changed rectangle. Examples walks through it.

Run without a board

The repository's development emulator runs the same disks. It needs GCC, and a ProDOS boot needs the enhanced //e ROM and SmartPort ROMs, which are not distributed: install them under build-inputs/native-roms/ as tools/DEPENDENCIES.md describes.

python tools/native_emulator.py --cc C:/msys64/ucrt64/bin/gcc.exe play --disk build/starfall.po --boot `
    --rom build-inputs/native-roms/Apple2e_Enhanced.rom `
    --slot7-rom build-inputs/native-roms/smartport_a2retronet_style_c700.mem `
    --slot7-c8-rom build-inputs/native-roms/smartport_a2retronet_style_c800.mem `
    --video-rom build-inputs/native-roms/apple2e-video.bin --profile vtw33

That wrapper runs without sound. The browser player plays a game with sound and speech in a web page. Emulator timing is a model: vtw33 runs at a nominal 33.33 MHz without every device wait, and turbo-f122 uses historical F1.2.2 TURBO costs. Only a board shows real timing and output.

A direct launch with --disk and --system instead of --boot uses the emulator's ProDOS MLI stand-in, which does not implement ALLOC_INTERRUPT. ti_audio_init then fails, so games that need the audio clock report that the slot-4 card is missing.
