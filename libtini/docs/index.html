libtini

A C game SDK for an enhanced Apple //e with Appletini. You write the game loop in C with cc65; libtini draws Super Hi-Res screens, keeps large data in RamWorks banks, plays Mockingboard or Phasor music, speaks through the SSI-263, reads the keyboard and joystick, and loads and saves ProDOS files.

The starter game's palette: sixteen 0RGB words that ti_gfx_begin writes to the SHR palette at AUX $9E00. Every pixel on a libtini screen is one of these sixteen entries, packed two to a byte.

libtini uses only interfaces that existing Appletini firmware already has: CPU writes to the Super Hi-Res screen, RamWorks bank selection, the slot-4 Mockingboard or Phasor, the slot-7 SmartPort through ProDOS, and the standard //e keyboard, buttons and paddles. It needs no firmware or FPGA change and no slot swapping. An optional build adds Appletini's private AMEM memory service for large banked copies; the default build leaves it out.

The library is MIT licensed, so games built with it can use any terms. It lives in the libtini/ folder of the appletini-software repository, with an example game, STARFALL, and a starter game to copy.

A first program

This program clears the screen, prints a line of text and waits for a key. Returning from main restores the text screen and quits to ProDOS.

#include "libtini.h"

static ti_surface screen;          /* zero-initialized, as create requires */
static const uint16_t palette[16] = {
    0x000, 0xFFF, 0xF00, 0x0F0, 0x00F, 0xFF0, 0x0FF, 0xF0F,
    0x888, 0x444, 0xF80, 0x08F, 0x8F0, 0xF08, 0x0F8, 0xCCC
};

int main(void)
{
    uint8_t key;
    if (ti_init(1, 2) != TI_OK) return 1;        /* RamWorks selectors 1 and 2 */
    if (ti_gfx_surface_create(&screen, 320, 200) != TI_OK) return 1;
    if (ti_gfx_begin(palette) != TI_OK) return 1; /* the screen now shows SHR */
    ti_gfx_clear(&screen, 0);
    ti_gfx_text(&screen, 8, 8, "HELLO FROM LIBTINI", 1);
    ti_gfx_present(&screen, 0, 0);                /* publish the whole surface */
    do ti_input_poll(); while (ti_input_key(&key) != TI_OK);
    return 0;                                     /* cleanup runs on return */
}

The surface lives in banked memory, not in C memory: it is a handle and an offset into the RamWorks banks that ti_init granted. Drawing changes the surface; ti_gfx_present copies it to the screen with ordinary CPU writes. Getting started shows how to build it into a bootable disk.

What the library covers

MemoryNear buffers, banked resources, bounded reads, writes, fills and copies. TimingFixed-rate updates from the audio device clock, independent of CPU speed. Graphics320x200 SHR, surfaces, rectangles, lines, text, sprites, tile maps, palettes. Sprite scenesA band renderer that redraws only the blocks that changed. AudioSix or twelve AY voices: event scores, pattern songs, effects, envelopes. SpeechSSI-263 phrases compiled from text, spoken numbers, a priority queue. InputKey events, held keys, buttons, raw paddles and calibrated stick directions. StorageWhole-file ProDOS reads and writes, and resource packs into banked memory. Optional AMEMProbed private acceleration for large banked transfers.

Host tools convert art, fonts, tile maps, speech text, music and MIDI files into data the library reads, package bootable ProDOS disks, profile functions on an emulator and build a browser version of a game.

Status

All modules have working source, example programs and host and emulator checks. The selected board baseline is existing Appletini firmware F1.3.2, commit 73de6fe03c31ad6f8ebfce3328704761fcd8c5a2. The owner has played STARFALL on a board and reported, by eye, that the joystick fix works and that play looks the same at 33 MHz and in TURBO; the effect volumes were set by listening. The release checks have not yet been run and recorded on a board. Timing figures in these pages come from emulator models unless they say otherwise. Checks and status lists what each kind of evidence covers.
