# Appletini Bosconian -- which arcade ROM graphic makes each SPR_ entry.
# Read by tools/bosco_rom.py together with a Bosconian ROM set you own
# (make ROMS=/path/to/bosco.zip). The repository holds no Namco data.
#
# Format
# ------
#   NAME: sprite N  color C [options]      16x16 sprite N (0..63) of bos1_13.5e
#   NAME: sprites A B C D color C [opts]   2x2 block of sprites (row-major) = 32x32
#   NAME: tile N    color C [options]      8x8 tile N (0..255) of bos1_14.5d
#   NAME: tiles A B C D color C [options]  2x2 block of tiles (row-major) = 16x16
#   NAME: tilemap W H cells... [options]   W x H tiles, each cell CODE:ATTR in hex
#                                          exactly as the game writes it to its
#                                          video RAM (attr: colour code in the low
#                                          6 bits, bit 6 clear = mirrored, bit 7 =
#                                          upside down), or .. for an empty cell
#   NAME: dot N [options]                  4x4 bullet dot N (0..7) of bos1-4.2r,
#                                          in the fixed bullet colours
#   NAME: ?                                not mapped: the drawn art in
#                                          sprites.txt is used for this entry
#   font: digits N letters N [space N] [minus N]
#                                          tiles that stand for '0'..'9',
#                                          'A'..'Z', ' ' and '-' in the font
#
# A line that starts with white space continues the previous line (handy for
# tilemap cells). C is the arcade colour code 0..63 (the attribute the game
# gives the object); build/rom/palettes.png shows the four colours of every
# code, and build/rom/sheet.png every tile, sprite and dot with its index.
# Numbers may be decimal or 0x hex.
#
# Options, applied in this order:
#   crop X Y W H     use only this part of the decoded graphic
#   fliph flipv      mirror; rot90 rot180 rot270 turn clockwise (square only)
#   fit              crop to the opaque pixels and center them in the SPR_
#                    box (default; sizes in docs/DESIGN.md section 9)
#   center           center the whole graphic (default for tilemap, whose
#                    size normally equals the box); pixels outside are lost
#   at X Y           put the graphic's top-left corner at X,Y in the box
#
# Arcade colours are turned into the nearest entry of palette 0 (DESIGN.md
# section 3); build/rom/colors.txt lists every colour that was used.
#
# Where the numbers come from
# ---------------------------
# The sprite ROM holds three headings of every ship (up, up-right, left; the
# board mirrors them for the other five), so the 8 headings are the three
# sprites plus fliph/flipv/rot180. The game's attract mode names the ships:
# 10 I TYPE, 18 P TYPE, 08 E TYPE, 20 SPY SHIP. Sprite colour codes are what
# the game puts in its sprite RAM; the tile grids of the bases, the mine and
# the asteroids are what it writes to the background tile RAM, and the
# destroyed cannons are its own replacement tables (sub CPU ROM). A base is
# split into a core that never changes and six cannon pods; a corner pod is
# 3x3 tiles because its strut is replaced together with it.

# panel: the lives icon is the 2x2 tile ship of the arcade panel (attribute
# 0x61: colour 0x21, not mirrored), the radar marker its base tile (colour
# 0x23 is the radar's own colour code), and the CONDITION caption its eight
# tiles: COND in the full font and ITION in the narrow one, without the
# blank first and last columns (62 px: a 64 px sprite's shifted variant
# would be 33 bytes, one more than the blitter copies)

    30:61 31:61
    32:61 33:61
ICON_BASE: tile 0x27 color 0x23
CAPTION_COND: tilemap 8 1
    0c:70 18:70 17:70 0d:70 37:70 3a:70 3b:70 3c:70
    crop 1 0 62 8
